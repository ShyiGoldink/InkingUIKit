# SBOX-02 · 2.5D 小沙盒「地表配色规格」

> **这是规格，不含实现代码、不生成图片。**
>
> 本文只给颜色常量与视觉判据。所有值都是可直接写进 C++ 的 `0xAARRGGBB`（alpha 在高字节）。
> 纹理一律程序生成、只用纯色与极简 1px 图案；不依赖任何 PNG / 外部资源，不描述贴图绘制流程，
> 也不要求修改 `examples/sandbox/docs/` 以外的任何文件。

- 任务：SBOX-02（与 SBOX-01 并行，不阻塞）
- 产出：`examples/sandbox/docs/art-palette.md`（唯一文件）
- 适用范围：静态骨架切片 —— 等距菱形瓦片地图 + 草地 / 沙地 / 水 / 石砖四种地表 +
  物体面一棵树 + 一格简易水面，纯展示。不做交互 / 角色 / 动画 / autotile。
- 可用视觉量：`InkingFieldTile` / `InkingFieldObject` 的 `texture` + `src` + `tint`
  + `flipX/flipY`，以及 `InkingField::SetSkyColor` / `SetGroundColor`。
- 视觉身份取向：**明度分层优先、色相次之、饱和度只做修饰**。IDE 主题是 light，
  但游戏内配色自定，本规格不跟随 IDE 主题。

---

## 1. 全局视觉约定（先定这四条，后面才不会打架）

1. **光源固定在屏幕左上方**（约 `(-1, -1)` 方向）。所有瓦片、树共用这一个光源，
   亮边 / 暗边方向全场一致。光照方向不统一，是等距画面最容易看出来的廉价感来源。
2. **`tint` 是乘性调制色，alpha 参与混合**（`InkingFieldObject::tint` 注释原文）。
   因此程序生成的纹理应画成**白 / 灰阶 relief**，不要预先染上地表色；否则同一份纹理
   换地表时会被 tint 二次染色，四种地表就得各做一张纹理。
3. **三档语义**：`Base` = 瓦片顶面大面积主色，**只靠它识别地表类型**；`Lit` = 上沿
   1px 受光棱；`Shade` = 下沿暗边 + 厚度侧面。`Lit/Shade` 是同一瓦片内部的小面积明暗，
   不承担"这是哪种地表"的判断，所以允许与别种地表的亮暗档明度重叠。
4. **命名与格式**：常量 `kPascalCase`（`docs/AGENTS.md` §3 第 3 条），颜色一律
   `0xAARRGGBB`（§6 第 106 条），集中在 `SandboxPalette.h` 一处，不在各调用点写字面值
   （§6 第 34 / 35 / 107 条）。

**明度标尺**：下文用加权感知亮度 `Y = 0.2126R + 0.7152G + 0.0722B`（0–255）作为可计算的
判据。它不是 CIE L*，但可复算、可断言，适合作为工程侧的回归线。

## 2. 四种地表

| 地表 | 色相 | 主色 `Base` | 亮档 `Lit` | 暗档 `Shade` | `Y(Base)` |
| - | - | - | - | - | - |
| 沙地 Sand | ≈40° 暖黄 | `0xFFE6C88C` | `0xFFF5DCA6` | `0xFFD3B57E` | **202** |
| 草地 Grass | ≈92° 黄绿 | `0xFF74A44B` | `0xFF8DBE63` | `0xFF5C8439` | **147** |
| 石砖 Stone | 无彩（S≈4%） | `0xFF6E7073` | `0xFF838587` | `0xFF595B5E` | **112** |
| 水 Water | ≈207° 冷蓝 | `0xFF26577E` | `0xFF316A94` | `0xFF1B4262` | **79** |

四个 `Base` 构成单调阶梯 `202 → 147 → 112 → 79`，相邻差 `55 / 35 / 33`，**最小 33**。
`Lit` 约等于 `Base` 提亮 18–20% 通道值，`Shade` 约等于压暗 20–25%，两者保持色相不变
（否则乘性 tint 会让高光偏色）。

### 2.1 在 64×32 菱形瓦片上凭什么一眼区分

- **沙地**：唯一暖黄相 + 全场最亮（`Y=202`）；即使完全去色，它也压过其余三者一整档，
  不靠饱和度就能认出来。
- **草地**：唯一绿相 + 次亮（`Y=147`）；与沙地差 55 明度、与石砖差 35，红绿色觉缺陷下
  草会偏黄褐、与沙同族，但明度差 55 仍把两者分开。
- **石砖**：唯一**无彩**色（`0xFF6E7073` 三通道只差 5）+ 中暗（`Y=112`）；它不跟任何
  有彩色抢色相，靠"零饱和 + 居中明度 + 十字砖缝"识别。
- **水**：唯一冷蓝有彩色 + 最暗（`Y=79`）；与石砖明度只差 33，但"有彩蓝 vs 无彩灰"
  再加横向波纹图案，是双通道兜底。

> 结论：四者在**色相**上分处暖黄 / 黄绿 / 无彩 / 冷蓝，在**明度**上分处四档互不重叠，
> 二者各自独立成立。饱和度只用来微调鲜活度，不承担识别。

### 2.2 程序生成的「极简图案」（第二编码通道，非必需但强烈建议）

都只是 1px 线条 / 点，画进同一张灰阶 relief 纹理，再由 `tint` 上色：

| 地表 | 图案 | 用什么色画 |
| - | - | - |
| 草地 | 3–5 根短斜线（草叶），低密度 | 该地表的 `Shade` |
| 沙地 | 稀疏 1px 点（沙粒），更低密度 | 该地表的 `Lit` |
| 水 | 2–3 条水平等距短波纹线 | 该地表的 `Lit` |
| 石砖 | 十字 / 工字形砖缝 1px 网格线 | 该地表的 `Shade` |

图案固定、不随机变化（静态骨架不做动画）；同一 `src` 可被四种地表复用，因为图案是灰阶的。

## 3. 物体层：树与简易水面

树 / 水面属于**物体面**，站在瓦片之上，不参与 §2 的四选一识别，因此不受"四档明度阶梯"
约束；但它们必须与脚下的地表拉开明度，否则会糊进背景。

| 部位 | 常量值 | 说明 |
| - | - | - |
| 树干 | `0xFF7B5230`（`Y≈88`） | 暖棕，比草地 `147` 暗 59，站得住 |
| 树干背光面 | `0xFF573A21`（`Y≈62`） | 圆柱左侧 / 右侧 1–2px 压暗，给出圆柱感 |
| 树冠 | `0xFF3E7838`（`Y≈103`） | 比草地更纯、更深、更冷的绿；与草地差 44，不会"树糊在草地上" |
| 树冠受光面 | `0xFF5C9B4F`（`Y≈136`） | 左上受光的一小块，面积不超过树冠 1/3 |
| 树冠背光面 | `0xFF2A5528`（`Y≈73`） | 右下暗部 + 底部 1px 轮廓 |
| 简易水面 | `0x994E9FD1`（alpha `0x99`） | 半透明淡青蓝水面层，叠在水瓦片上 |
| 水面波纹高光（可选） | `0xB2CDEBF5`（alpha `0xB2`） | 1–2 条横向亮线，制造"水在反光" |

### 3.1 水面 alpha 建议

- **建议区间 `0x80`–`0xB3`（50%–70%），主值取 `0x99`（153/255 ≈ 60%）**。
  叠在 `kWaterBase`（`Y≈79`）上，混合后约 `Y≈119`，既明显亮出一层面，又透得出底下的
  深色水瓦片与波纹，"水光"感就出来了。
- **不要用 `0x00`**：`tint` 的 alpha 参与混合，alpha 为 0 的物体**不可见也不可点**
  （`HitObject` 明确排除）。静态切片虽然不做交互，但后续加交互时这颗雷会炸。
  想让水面不吃点击，应该设 `hitEnabled = false`，而不是把 alpha 降到 0。
- **不要用 `0xFF`**：完全盖住底下瓦片，"水面层"就退化成第二块不透明水瓦片，白叠一层。
- 低于 `0x66`（40%）在深色底上几乎看不见；高于 `0xCC`（80%）近乎不透明。
- 注意区分：`docs/AGENTS.md` §6 第 52 条那条"只占位不露面就给 alpha 2/255"是 **UI 三态色**
  的规矩，不适用于 field 层；field 的命中判据直接看 `tint` 的 alpha。

## 4. 天空底色 / 地面底色

| 接口 | 建议值 | 理由 |
| - | - | - |
| `SetSkyColor` | `0xFF8FAEC6`（`Y≈169`） | 低饱和雾蓝，明快但不刺眼；比沙地 / 草地暗，让瓦片成为画面最亮的一层 |
| `SetGroundColor` | `0xFF31363D`（`Y≈53`） | 深中性炭灰，暗于四种地表中最暗的水（`79`），且无彩 |

> **地面底色是瓦片没铺到的兜底，别抢戏**：它只在缝隙与地图边缘露出来，必须最暗、
> 最不饱和，读成"阴影 / 虚空"，绝不能被误认成第五种地表（尤其不能像水）。

- 两个接口都**必须显式覆盖**：库内默认值是 `0xFF000000`（天空）/ `0xFF1E1E1E`（地面），
  不覆盖会让画面整体偏黑。
- ⚠ **Grid 模式下 `SetSkyColor` 设了不生效**（`docs/AGENTS.md` §7 静默失效清单第 18 条、
  `docs/zh/api/InkingField.md` §7 第 2 条：`s ≡ 1`、地平线在无穷远 ⇒ 天空带高度为 0）。
  若静态骨架用 `Mode::Grid`，请把 `0xFF8FAEC6` 改设到窗口层 `SetBackdrop` 上，
  或改用 `Mode::Oblique` + `horizonRatio` 让天空带真的出现。**这是 P0 对齐项**，见 §7。

## 5. 等距菱形瓦片的明暗、描边与厚度

只描述「程序生成一张 64×32 RGBA 纹理时，哪些像素填什么色」，全部是 1px 线条 / 实心填充，
不涉任何贴图资源或绘制流程实现。

几何基准：菱形四顶点 `上(32,0) / 右(64,16) / 下(32,32) / 左(0,16)`，四角透明。

1. **顶面**：平涂该地表 `Base`。**不要在顶面做渐变** —— 顶面一旦渐变，每个地表就要多
   维护一张纹理，而明暗完全可以交给下面两条边；保持平涂是最省、最一致的做法。
2. **哪两条边亮**：**上沿 V** —— 左上边（左→上）与右上边（上→右），各画 1px
   内描边，填该地表 `Lit`。对应"光从屏幕左上来"的全局约定。
   **下沿 V** —— 右下边（右→下）与左下边（下→左），各画 1px 内描边，填该地表 `Shade`。
3. **厚度**：沿下沿 V 向菱形**内侧**再填 2px 带状区域为 `Shade`，读作薄板的可见侧面。
   **厚度画在 64×32 内部，不向外挤出**：瓦片仍是严格的 64×32，与 `cellWidth/cellDepth`
   对齐，不会撑出格边界造成相邻格重叠或露缝。
4. **是否描边：要描。** 整块（顶面 + 侧面）外轮廓 1px `kTileOutline = 0xFF232A31`。
   同色瓦片相邻时，这 1px 是唯一的分离依据，不能省；`docs/AGENTS.md` §6 第 105 条
   也把"一圈极细描边"列为纯色块之间最便宜、最稳的分层手段。
   - 默认用实色 `0xFF232A31`（最简单、最确定）。
   - 可选更柔和的叠压式半透明黑 `kTileOutlineSoft = 0x80202830`：一个常量通吃四种地表，
     不会在深色水瓦片上"描边消失"、在浅色沙地上又过硬。**前提**是纹理 / 混合链支持 RGBA
     半透明像素，见 §7 对齐项 B；不支持就退回实色描边。
5. **别默认叠阴影**：`docs/AGENTS.md` §6 第 112 条记录过"偏移为 0 的默认阴影把整幅画面
   压暗一层"。厚度只画在明确的下沿 2px，不做全瓦片半透明蒙层。
6. **flip 会翻掉光源**：`flipX/flipY` 只翻 UV 不翻几何，镜像一张瓦片会把亮边翻到右下，
   与全局光源冲突。静态骨架瓦片数量少，**建议完全不用 flip**；若必须复用，请另出一份
   `src` 并同步交换亮 / 暗边。

## 6. 可访问性

- **分级：Basic**（静态展示、无交互、无文本、无状态提示）。本切片只需满足两条：
  ① 关键信息不单靠颜色编码；② 四种地表在去色（灰度）下两两可分辨。
  后续 UX 规格（若由文策渊产出）须引用此分级，不可擅自降级。
- **明度差下限：四个 `Base` 的 `Y` 两两差 ≥ 30（0–255 标度）**，当前实测
  `202 / 147 / 112 / 79`，相邻最小差 **33**，达标。
- **一句话结论**：在红绿色弱 / 红绿色盲 / 蓝黄色弱乃至全色盲下**仍可区分** —— 明度阶梯
  独立承载了类型信息，色相只是冗余增强；此外 §2.2 的极简图案提供第二编码通道
  （石砖砖缝、水波纹、草叶、沙粒）。**若后续换色导致 `ΔY < 30`，图案从"建议"升为
  "必须"**，且不得再砍掉 §5 的 1px 描边。

## 7. 给工程的对齐项（需主理人中转 engineering-lead，不直连）

| # | 级别 | 事项 |
| - | - | - |
| A | **P0** | Grid 模式下 `SetSkyColor` 不生效、`GetSkyBand()` 高为 0。静态骨架若用 Grid，`kSkyColor` 需改走窗口层 `SetBackdrop`；否则天空是黑的。请确认最终投影模式。 |
| B | **P0** | `kWaterSurface` / `kWaterGlint` / `kTileOutlineSoft` 都依赖 `SDL_BLENDMODE_BLEND` **显式开启**（`AGENTS.md` §6 第 32 条），离屏自检也要自己开；否则 alpha 表现为硬边或整层不生效。不支持则水面退回不透明、描边退回实色。 |
| C | **P0** | 确认 `tint` 按"乘性调制 + alpha 混合"落地。程序生成纹理请画成白 / 灰阶 relief，不要预染地表色，否则四地表要各出一张纹理且换色会二次染色。 |
| D | **P1** | `AGENTS.md` §3 第 3 条禁止 CPU 逐像素光栅化：纹理只在初始化时一次性生成 RGBA 像素缓冲并上传为句柄，之后每帧仍走正常 `SetTiles` / `SetObjects` 提交。§5 描述的是**这张纹理的内容**，不是渲染路径。 |
| E | **P1** | 水面若放在物体面，`InkingFieldObject` 在屏幕上是**正矩形**、不斜（API 文档 §4），不会贴合成 64×32 菱形格。请定落位：①把水光做成地形面 `InkingFieldTile`，或 ②物体纹理自带菱形透明角、接受它是一层矩形高光。 |
| F | **P1** | 物体没有有效 `texture` 句柄就**不可见也不可点**（API 文档 §7 第 3 条）：树与水面都必须给有效句柄，不能只填 `tint`。 |
| G | **P1** | `InkingFieldObject` 实际只有 `flipX` + `rotation`，**没有 `flipY`**（头文件如此，`InkingFieldTile` 才有 `flipX/flipY`）。树 / 水面若要上下翻转，需走 `rotation` 或另出 `src`。 |
| H | **P2** | 显式覆盖 `SetSkyColor` / `SetGroundColor` 默认值 `0xFF000000` / `0xFF1E1E1E`。 |
| I | **P2** | 常量集中到 `SandboxPalette.h`（`kPascalCase` + `0xAARRGGBB`），不要在瓦片构造处散落字面值。 |

**标注偏离**：本规格的 `kSkyColor` / `kGroundColor` 是对库默认值的**有意覆盖**；
`kTileOutlineSoft`、`kWaterGlint`、§2.2 的四组图案是**可选增强**，超出最小可运行骨架，
若工程侧确认不支持可直接砍掉，不影响 §2 与 §6 的达标。
