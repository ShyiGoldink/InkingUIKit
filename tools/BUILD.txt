!! 先说清楚"预览"是什么意思

   预览版**不是** 1.0 的发布版。1.0 的功能面（组件、动态档、输入、渲染、生成器）
   已经收齐，所以这份包可以拿去集成、可以当验收基线；但「哪些公开符号是承诺、
   哪些还能改」这次的盘点还没做（立项见
   `docs/zh/plans/2026-10-29-evidence-and-delivery.md` 的「1.0.0 的 ABI 冻结」
   一行，明确写着"不在本批"）。所以：**接口 / ABI 仍可能在正式版前变化，
   升级请整包重编**。正式 `1.0.0` 发出时，被点到名的符号才进入冻结承诺。
   功能面与 `0.9.2` 相同——本版只动版本常量与文档，另加两处打包脚本修复
   （见「验证记录」第 4 条）。

!! 升级提示：0.8.5 → 1.0.0-preview（中间跨了 0.9.0 / 0.9.1 / 0.9.2）

   破坏性（0.9.0，**所有消费方必须整包重编**）：
     1. **去掉 `namespace inking` 外壳**：公开符号全部改到全局命名空间 + `Inking`
        前缀（类型 126 个、自由函数 119 个、常量 33 个）。`inking::ButtonData` →
        `InkingButtonData`、`inking::SetDesignSize` → `InkingSetDesignSize`、
        `inking::kVersion` → `InkingVersion`；子命名空间 `inking::detail` /
        `inking::prefab` / `inking::json` → `inking_detail` / `inking_prefab` /
        `inking_json`；生成代码默认命名空间 `inking::cxxcss` → `cxxcss`。
        **头文件路径与 CMake 目标名没变**（`#include <button/ButtonData.h>`、
        `inking::inking` 照旧）。
     2. **`InkingSpriteGroup` 改名为 `InkingAnimateGroup`**（旧名让给"一个 sprite
        由多块拼成"的新组件；纯重命名，`SwitchTo` / `animationChanged` / `keepPhase`
        语义全不变）。连带 `…Data` / `…ModuleName`。
     3. **`InkingSpriteLike::Hooks` 两个回调换签名**：
        `setSourceRect(const InkingShapeBounds&)` →
        `setSourceRects(const InkingShapeBounds*, std::size_t)`；
        `LoadedFrame::sourceRect` → `sourceRects`（矩形表）。
        自己派生过 `InkingSpriteLike` 并填 `Hooks` 的代码要重写（仓里没有这种代码）。
   行为变化（都是"以前静默，现在按文档说的做"）：
     4. **`Capture()` / `RenderToTexture()` 现在真的含 letterbox 留白**（0.9.2 修）：
        以前逻辑呈现开着时 `SDL_RenderReadPixels` 只回逻辑画布那块，比例不一致的
        窗口截出来的构图与眼睛看到的不同。**按旧行为写过分镜 / 比对脚本的要对一遍。**
     5. **未选中的 Checkbox / Radio 不再画 mark**（0.9.1 修）：以前那个勾常驻。
     6. **单选组互斥现在真的生效**（0.9.2 修 `RadioGroup::Add` 只建半边链接）：
        `Add` 之后成员知道自己属于哪个组，三个圈不再能同时选中。
        用 `SetGroup` 的既有代码一个字节都不变。
   新增能力（不改既有代码，用得上才改）：
     7. **动态面板能滚轮了**（0.9.1）：静态档与动态档共用一份换算
        （`InkingApplyWheelToScroll`，步长 `wheelStep` 设计像素），一帧的滚轮只落
        在一个接收者身上（不双滚）。配套 `InkingScene::GetPointerWheelTarget` /
        `GetTopmostDynamicAt` 两个只读查询。
     8. **背景板**（0.9.2）：`InkingWindow::SetBackdrop` / `SetBackdropImage`，
        画在清屏之后、场景之前，覆盖整幅窗口像素（黑边填的就是它）；
        配置是 `window.backdrop` / `window.backdropImage`。
     9. **块叠加组**（0.9.0）：`InkingSpriteGroup`（静态）/
        `InkingDynamicSpriteGroup`（动态）——一帧 K 块仍然只有一次
        `SDL_RenderGeometry`（自检钉住 K=1/2/4 都是 1）。
    10. **四个组件的动态档 + UIKit 齐全度 a~f 批**（0.9.0）：`DynamicImage` /
        `DynamicSprite` / `DynamicLabel` / `DynamicPanel`、TabBar、勾选三件套、
        浮层三件套、Slider / ProgressBar、光标形状 + 文件拖放。
   完整迁移样板见 `docs/zh/CHANGELOG.md` 的「0.9.0 / 变更（破坏性）」与
   「0.5.0 / 变更」（更老的指针钩子签名变更）。

本版内容（1.0.0-preview = 0.9.2 的功能面；下面按 0.9.x 的五组净增量列）
  - **几何分档收口**：帧机泛化成"每帧一组矩形"，块叠加组一帧 K 块仍然只有一次
    `SDL_RenderGeometry`（自检钉住 K=1/2/4 都是 1）。
  - **命名收口**（0.9.0 N 系列）：去 `namespace inking`、统一 `Inking` 前缀；
    并把 `project(VERSION)` 从 0.7.1 补到当前版本——旧包的
    `inkingConfigVersion.cmake` 写的是 0.7.1，下游 `find_package(inking 0.8.5)`
    会直接失败（这条 0.9.0 一并修掉）。
  - **UIKit 齐全度 a~f 批**（0.9.0）：视频真出画、计量两件套（Slider /
    ProgressBar）、勾选三件套、浮层三件套、TabBar、光标形状 + 文件拖放。
  - **动态档滚轮**（0.9.1）：逻辑步读不可靠（实测喂 30.0 只读到 20.0、61 帧里
    11 帧为 0），改成每渲染帧一次的回调读；推 / 拉两条入口共用一份算术，
    四道门判归属防双滚。
  - **背景板**（0.9.2）：`SetBackdrop` / `SetBackdropImage`，黑边可配色 / 铺图，
    `$token` 每帧查主题表；顺带修掉"截图其实没含留白"。

验证记录（**本版实测**，2026-11-04，构建树 `build-release`）

  1. 构建：`cmake --build build-release --clean-first -j` 全绿；`strict_warnings`
     门（同一批源 + `-Wall -Wextra -Wshadow -Wcast-qual -Wuseless-cast -Werror`）
     通过 ⇒ 库与生成器那批源零告警。
     （过程中有一次 cc1plus 卡在 `TextEditState.cpp` 上 20 分钟、CPU 只用了
     0.015 s，强杀后原样重跑 8 秒完成——本机偶发，与本版代码无关，记在这里
     免得下次误判成"编译器挂了"。）
  2. `ctest --test-dir build-release` ⇒ **8/8 passed**：配置校验 / 字段表对账 /
     生成链路编译 / 静默清单对账 / `strict_warnings`（14.2 s）/ 行为自检
     （software）/ 行为自检（真后端）/ `probe_template`。
  3. 行为自检（构建树）⇒ **925 项 ok / 1 项 skip / 0 项失败**，退出码 0；
     `INKING_SELFTEST_DRIVER=windows` 同数 925 / 1 / 0。那条 skip 是
     「窗口没拿到输入焦点（后台 / CI）」的悬停类断言——环境不是缺陷。

怎么用
  1. 只想看效果：双击 bin/inking_demo.exe（ESC 退出，F11 全屏，右键有上下文事件）；
     或命令行跑 bin/inking_demo_selftest.exe，读末行"失败项：N"（退出码 = 失败项数，
     `ctest` 也是这么判的）。
     **不需要 MSYS2、不需要改 PATH**——DLL 就在 exe 旁边。
  2. 写自己的工程：见 README「用预编译包」两条路线；最快的是把
     examples/minimal/ 整份拷出去改：
       cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release \
             -DCMAKE_PREFIX_PATH="<本包根>;C:/msys64/ucrt64"
       cmake --build build
     把 <本包>/bin/*.dll 拷到 exe 旁（minimal 的 CMakeLists 已自动做）。
  3. 前提：编译需要 MSYS2 UCRT64 的 cmake / ninja / gcc / sdl3 四件 / ffmpeg。
     **不能用 MSVC 链接本包**（MinGW 的 .dll.a 与 MSVC 的 .lib 不兼容）。
  4. 升级旧代码先看本文件顶部的「升级提示」与 CHANGELOG：0.9.0 的命名空间收口
     与两处改名是**破坏性**的（整包重编）；0.5.0 的指针钩子签名同样。
  5. 排错先截图：设 `INK_CAPTURE=<路径>` 跑一次，比加日志快。
  6. 跑自检会在 exe 旁生成 LOG/ 目录（日志），不属于包内容，可删。

已知限制（详见 README「已知限制」）
  - **预览版不冻结**：接口 / ABI 仍可能在正式 1.0.0 前变（见文件头第一节）。
  - 只在 Windows + MSYS2 UCRT64 + Ninja 构建过；Linux / macOS 未验证。
  - **包体积 57 MB**：FFmpeg 的传递闭包占绝大部分（101 个 DLL）；要小包得关掉
    视频支持重编，而不是删 DLL。
  - **许可证口径**：闭包里的 GPL 组件（x264 / x265 等）不适用本仓库的 MIT，
    对外发布前需确认源码提供方式。
  - 中键只记状态、不派发；右键不产生 onPointerDrag；触摸只认第一根手指。
  - 长按阈值 0.5s / slop 8 设计像素是通用值，真机手感未调。
  - 单行输入框：多行、撤销 / 重做、Tab 焦点遍历、IME 候选窗定位未做。
  - 两种 svg 的边界不同：按钮的 AppearanceType::Svg 只认单图形（生成期转形状）；
    整张设计稿用 Image 的 type:"svg"（运行期按目标像素光栅化）。
  - SVG 里的 text / use / <image> / clipPath / mask / filter 不渲染，只打一条 WARN；
    导出时请把文字转曲、use 展开。整张稿也**不做元素级拆解**。
  - 没有 portal：子的 z 盖不过父级的兄弟，要压就抬容器自己。
  - 运行期换肤只覆盖颜色（按钮三态 / 面板两态 / 标签文字色）；字号 token 是编译期的。
  - 背景板底图只做 cover（stretch / tile / 九宫格没做），且**不进主题表**——
    切主题换底图要改配置。
  - 透明窗口只在部分后端成立（D3D11 实测可用；D3D12 / Vulkan 多数不行）。
  - **抗锯齿（羽化）带仍按设计像素**（`kFeatherPixels = 1.0f`）：R≠1 时边缘那圈会失真。
    它与素材分辨率**无关**，按设备像素改造推迟到 1.x.x。
  - **比例锁没有**：`SDL_WINDOW_RESIZABLE` 恒开且未调 `SDL_SetWindowAspectRatio`，
    用户自由拖拽时 letterbox 留白必然出现——这是"UI 永不变形"的代价。
  - **素材偏小只在 DEBUG 构建里提示**：发布包没有任何日志。
  - **采样模式是进程级的**：像素素材与高清图平滑缩放同一进程只能二选一；
    且 software 后端的几何批不认采样模式（`SDL_RenderGeometry` 恒最近邻）。
  - **图集描述不能热更**：结构（帧矩形）进 exe，只有图片字节在 assets/ 里。
  - **嵌套两层滚动容器只有外层生效**：`FindSubtreeWheelOwner` 给的是"最近的声明者"，
    要内层优先得按指针路径逐层仲裁。一层是对的。
  - **文字纹理预算的瞬时上界是"预算 + 本帧新增"**：淘汰只发生在帧首，本帧刚烘出来的
    纹理不能丢（丢了当场缺字）；字形图集不参与淘汰。

重新打包（维护者，三条命令）
  1. cmake --build build-release -j        ← 先构建。**不构建就打包会被第 3 步拦下**
  2. 改本文件（tools/BUILD.txt 是**手写母本**，脚本只拷贝、不会生成）：
     版本行 / 构建日期 / 产物哈希 / 本版内容 / 验证记录
  3. bash tools/package.sh                 ← 产出 dist/inking-<版本>[-<阶段>]-win64/
                                             + .zip + .SHA256SUMS.txt

  第 3 步开头有两道**护栏**：`include/inking.h`（版本号的唯一真相）比
  `build-release/bin/libinking.dll` 新时**直接失败**，并提示先重建；缺
  `inking_demo_selftest.exe` 也失败。理由：版本号与二进制原本互不比对，忘了重建
  会静默打出"标着新版本、装着旧代码"的包（文件名、BUILD.txt、校验和全都自洽，
  只有代码是旧的）。它抓不住"改了代码但忘了 bump 版本号"——那属于版本纪律。
