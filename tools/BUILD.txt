!! 先说清楚"预览"是什么意思

   预览版**不是** 1.5.0 的发布版。功能面（组件、动态档、输入、渲染、生成器、
   场地层、拖拽原语、本版新增的天空）已经收齐，所以这份包
   可以拿去集成、可以当验收基线；但「哪些公开符号是承诺、哪些还能改」的盘点
   还没做（立项见 `docs/zh/plans/2026-10-29-evidence-and-delivery.md` 的
   「1.0.0 的 ABI 冻结」一行）。所以：**接口 / ABI 仍可能在正式版前变化，
   升级请整包重编**。正式版发出时，被点到名的符号才进入冻结承诺。

!! 升级提示：1.4.0-preview → 1.5.0（**有 ABI 变化，必须整包重编**）

   先看这一条（唯一会崩的地方）：
     **`InkingFieldProjection` 变大了**（尾部多两个字段：`horizonRatio` 与
     `skyFit`）。它是**按值 / const 引用跨 DLL 传递**的参数结构，消费方在
     自己的 TU 里构造它，所以头文件、`libinking.dll`、导入库必须是**同一次
     构建**的三件。老代码不写新字段 ⇒ 缺省 `-1` / `Cover` ⇒ 行为与 1.4.0 一致
     （逐位，自检里有回归门）。

   **换 SDK 目录时消费方必须 clean 重编**（GoldingCore 那边实测过）：CMake / ninja
   的依赖文件记的是**旧 SDK 的绝对路径**，把 `include` 指到新目录**不会**让旧
   `.obj` 失效（`ninja -n` 报 "no work to do"），于是 exe 还是按旧头编的、却链上
   了新 dll —— 正是上一段那句"新旧混跑必崩"。要么 `ninja -C build clean` 再编，
   要么换一个干净的构建目录。

   **没有可见行为变化**：不设 `horizonRatio` / `SetSkyTexture` 的场景，画面与 1.4.0
   完全一样（`InkingWidget` 这一版没动，控件布局不变）。

   新增能力（用得上才改）：
     1. `InkingFieldProjection::horizonRatio`：**地平线位置**（天空占画布高度的
        比例，`[0, 1)`；`-1` = 不覆盖）。库内部反解 `farD` 保证几何自洽，**不改**
        `skew` / `depthScaleFar` / `zoom` 的语义。反解值用
        `InkingFieldEffectiveFarD()` 查，`Projection()` 里也是它。
     2. `InkingSkyFit`（`Cover` / `Stretch` / `Tile`）+ 同名字段：天空贴图的铺法。
     3. `InkingField::SetSkyTexture(handle)`：天空贴图（无效句柄 = 回到纯色）。
        句柄所有权在调用方，库不加载 / 不释放 / 不缓存路径；每帧换句柄零成本。
     4. `InkingField::GetSkyBand()`：当前天空带的设计坐标矩形（没有天空时高 0）。
     5. `InkingField::Stats::skyQuads`：上一帧天空贴图提交了几个四边形。

   这一版**没有**动：控件、拖拽、命中表、层序、地面瓦片、生成器。

   从 1.3.x 或更早升上来，还要看 1.4.0 的 `InkingWidget` 变大那一条
   （见 `docs/zh/CHANGELOG.md` 的 1.4.0-preview 一节）。

!! 如果你从 0.8.5 或更早升上来，先看下面这段（**破坏性**）

   破坏性（0.9.0，**所有消费方必须整包重编**）：
     1. **去掉 `namespace inking` 外壳**：公开符号全部改到全局命名空间 + `Inking`
        前缀（类型 126 个、自由函数 119 个、常量 33 个）。`inking::ButtonData` →
        `InkingButtonData`、`inking::SetDesignSize` → `InkingSetDesignSize`、
        `inking::kVersion` → `InkingVersion`；子命名空间 `inking::detail` /
        `inking::prefab` / `inking::json` → `inking_detail` / `inking_prefab` /
        `inking_json`；生成代码默认命名空间 `inking::cxxcss` → `cxxcss`。
        **头文件路径与 CMake 目标名没变**（`#include <button/ButtonData.h>`、
        `inking::inking` 照旧）。
     2. **`InkingSpriteGroup` 改名为 `InkingAnimateGroup`**（旧名让给"一个 sprite
        由多块拼成"的新组件；纯重命名，`SwitchTo` / `animationChanged` / `keepPhase`
        语义全不变）。连带 `…Data` / `…ModuleName`。
     3. **`InkingSpriteLike::Hooks` 两个回调换签名**：
        `setSourceRect(const InkingShapeBounds&)` →
        `setSourceRects(const InkingShapeBounds*, std::size_t)`；
        `LoadedFrame::sourceRect` → `sourceRects`（矩形表）。
        自己派生过 `InkingSpriteLike` 并填 `Hooks` 的代码要重写（仓里没有这种代码）。
   行为变化（都是"以前静默，现在按文档说的做"）：
     4. **`Capture()` / `RenderToTexture()` 现在真的含 letterbox 留白**（0.9.2 修）：
        以前逻辑呈现开着时 `SDL_RenderReadPixels` 只回逻辑画布那块，比例不一致的
        窗口截出来的构图与眼睛看到的不同。**按旧行为写过分镜 / 比对脚本的要对一遍。**
     5. **未选中的 Checkbox / Radio 不再画 mark**（0.9.1 修）：以前那个勾常驻。
     6. **单选组互斥现在真的生效**（0.9.2 修 `RadioGroup::Add` 只建半边链接）：
        `Add` 之后成员知道自己属于哪个组，三个圈不再能同时选中。
        用 `SetGroup` 的既有代码一个字节都不变。
   新增能力（不改既有代码，用得上才改）：
     7. **动态面板能滚轮了**（0.9.1）：静态档与动态档共用一份换算
        （`InkingApplyWheelToScroll`，步长 `wheelStep` 设计像素），一帧的滚轮只落
        在一个接收者身上（不双滚）。配套 `InkingScene::GetPointerWheelTarget` /
        `GetTopmostDynamicAt` 两个只读查询。
     8. **背景板**（0.9.2）：`InkingWindow::SetBackdrop` / `SetBackdropImage`，
        画在清屏之后、场景之前，覆盖整幅窗口像素（黑边填的就是它）；
        配置是 `window.backdrop` / `window.backdropImage`。
     9. **块叠加组**（0.9.0）：`InkingSpriteGroup`（静态）/
        `InkingDynamicSpriteGroup`（动态）——一帧 K 块仍然只有一次
        `SDL_RenderGeometry`（自检钉住 K=1/2/4 都是 1）。
    10. **四个组件的动态档 + UIKit 齐全度 a~f 批**（0.9.0）：`DynamicImage` /
        `DynamicSprite` / `DynamicLabel` / `DynamicPanel`、TabBar、勾选三件套、
        浮层三件套、Slider / ProgressBar、光标形状 + 文件拖放。
   完整迁移样板见 `docs/zh/CHANGELOG.md` 的「0.9.0 / 变更（破坏性）」与
   「0.5.0 / 变更」（更老的指针钩子签名变更）。

本版内容（1.5.0 = 1.4.0 的功能面 + 天空：地平线位置可设 / 天空可贴图）

  - **地平线位置终于可设了**（本版主线，任务书 `TASK-SDK-SKY.md`）：以前地平线是
    **导出量**（`horizonY = H − cos(skew)·zoom/h`），只能靠 `skew` / `zoom` /
    `depthScaleFar` / `farD` 间接影响。现在 `horizonRatio` 直接指定"天空占画面
    多少"，库内部**反解 `farD`** 让几何保持自洽。
  - **为什么反解 `farD` 而不是只裁地面带**：`h` 变大以后**每一格都变矮**（唯一
    不动的是 `ld = 0` 那条底边）。只裁地面带会让格子比例与灭点对不上，症状是
    "地面从天空里穿出来"，看起来像美术画错了——自检里有一条专门钉"最近一格也
    变矮了"，防的就是这种实现。
  - **天空贴图**：`SetSkyTexture(handle)` + `InkingSkyFit` 三档
    （`Cover` 等比铺满并居中裁切 / `Stretch` 拉伸 / `Tile` 原始像素 1:1 平铺）。
    贴图只画在天空带内；有贴图就**不画纯色**（两者不混用，叠一层半透明底色会
    让颜色偏掉）。
  - **纯标量 / 纯句柄**：没有回调、没有动画抽象、库不读时钟——提出方的代码生成器
    要把这两个参数逐个输出成 `constexpr`。动态天空 = 消费方每帧换句柄。
  - **一个坑写进了代码**：`ensureCache()` 每帧用进程设计尺寸覆盖 `designWidth /
    height`，但 `horizonRatio` 是**比例**、不跟着覆盖（否则"编辑器里对、跑起来
    不对"）。
  - **设了不生效不再沉默**：格子模式 / 平行投影下天空带高度为 0，贴图被忽略并
    打一条 WARN（静默失效清单第 22 条 `field_sky_texture_inert`）。
  - 自检新增 `CheckFieldSky`（28 条断言）：覆盖生效 / 换 `depthScaleFar` 地平线
    不动 / `-1` 逐位回归门 / 逐格压缩 76.2→73.3 且越远压得越狠 / 五条拒绝规则 /
    天空带 / `Cover` 与 `Tile` 的块数 / 一千次换句柄零加载 / Grid 模式一条 WARN。

验证记录（**本版实测**，2026-11-10，构建树 `build-release`）

  1. 构建：`cmake --build build-release -j` 全绿；`strict_warnings` 门（同一批源
     + `-Wall -Wextra -Wshadow -Wcast-qual -Wuseless-cast -Werror`）通过 ⇒
     改动的 `src/field/InkingField.cpp` / `InkingFieldProjection.cpp` 也在门内、
     零告警。
  2. `ctest --test-dir build-release` ⇒ **10/10 passed**：配置校验 / 字段表对账 /
     生成链路编译 / 静默清单对账 / `field_pure_headers_have_no_sdl` /
     `strict_warnings` / 行为自检（software）/ 行为自检（真后端）/
     `probe_template` / `probe_drag`。
  3. 行为自检 ⇒ **1095 项 ok / 0 项失败**，退出码 0（1.4.0 是 1069 项：本版
     `CheckFieldSky` 新增 28 条，另有几条既有断言随版本号变化）。
  4. **这一版的关键实测数字**（都是断言，不是"看起来对"）：
     - `horizonRatio = 0.30`、`H = 1080` ⇒ `InkingFieldHorizonY = 324.00`；
       同一比例把 `depthScaleFar` 从 0.9 改成 0.5，地平线仍是 324.00，而反解出的
       `farD` 从 63.42 变成 570.82（说明变量确实是 `farD`）；
     - 缺省 `-1` 时 `InkingFieldEffectiveFarD == projection.farD` **逐位相等**，
       地平线与 1.4.0 算式 `-6548.6641` 一致（老配置零位移）；
     - 逐格压缩：天空 30% ⇒ 76.22 / 62.26 / 51.81 px，50% ⇒ 73.26 / 55.76 /
       43.86 px；第 1 格降 2.96 px（**最近一格也变矮**）、第 3 格降 7.95 px
       （越远压得越狠）；
     - 贴图：`Cover` 只提交 1 个四边形、换天空色逐像素不变（不混用）、地面带
       像素不变；`Tile` 在 1280×216 的带上用 192×48 的图 ⇒ 7×5 = 35 块；
       1000 次 `SetSkyTexture` ⇒ `loads` 零增长；
     - `Grid` 模式：天空带高 0、`skyQuads = 0`、WARN 恰好 1 条（渲染两帧也不
       重复）。
  5. **包内验收**（`env -i`，PATH 只留 `C://Windows//system32` 与 `C://Windows`，
     模拟只拿到 zip 的机器）：
     - `bin/inking_demo_selftest.exe` ⇒ 自检全绿（末行「失败项：0」）；
     - `bin/inking_demo.exe` 起窗正常。
  6. 完整性：**356 个文件**（355 条校验和 + `BUILD.txt` 自己不计入）、`SHA256SUMS.txt` 逐条 OK、zip 356 条目、
     顶层目录 `inking-1.5.0-preview-win64/`、解包 152 MiB、zip 57 MB。
  7. **没验的项**（写清楚，别当成验过）：
     - **天空贴图的观感没人眼确认**：自检只保证"贴图真的提交了、不盖地面、
       不掺纯色、块数对得上"；`Cover` 裁在哪种画面上好看、`Tile` 的接缝是否明显，
       只能拿 GoldingCore 那边看；
     - **裁剪与地面带的重叠**在像素上观察不到（地面带后画，会盖住任何溢出），
       所以 `ClipToSkyBand` 只由"块数 / UV 比例"这类间接判据撑着；
     - 真后端下的天空（D3D11）只跑了 `selftest_windows` 的既有用例，没有专门的
       天空像素基线；
     - 触摸 / 多窗口 / 高分屏下的天空贴图**没验**；
     - Linux / macOS 从未构建。

怎么用
  1. 只想看效果：双击 bin/inking_demo.exe（ESC 退出，F11 全屏，右键有上下文事件）；
     或命令行跑 bin/inking_demo_selftest.exe，读末行"失败项：N"（退出码 = 失败项数，
     `ctest` 也是这么判的）。
     **不需要 MSYS2、不需要改 PATH**——DLL 就在 exe 旁边。
  2. 写自己的工程：见 README「用预编译包」两条路线；最快的是把
     examples/minimal/ 整份拷出去改：
       cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release \
             -DCMAKE_PREFIX_PATH="<本包根>;C:/msys64/ucrt64"
       cmake --build build
     把 <本包>/bin/*.dll 拷到 exe 旁（minimal 的 CMakeLists 已自动做）。
  3. 前提：编译需要 MSYS2 UCRT64 的 cmake / ninja / gcc / sdl3 四件 / ffmpeg。
     **不能用 MSVC 链接本包**（MinGW 的 .dll.a 与 MSVC 的 .lib 不兼容）。
  4. 升级旧代码先看本文件顶部的「升级提示」与 CHANGELOG：0.9.0 的命名空间收口
     与两处改名是**破坏性**的（整包重编）；0.5.0 的指针钩子签名同样。
  5. 排错先截图：设 `INK_CAPTURE=<路径>` 跑一次，比加日志快。
  6. 跑自检会在 exe 旁生成 LOG/ 目录（日志），不属于包内容，可删。

已知限制（详见 README「已知限制」）
  - **预览版不冻结**：接口 / ABI 仍可能在正式版前变（见文件头第一节）。
  - 只在 Windows + MSYS2 UCRT64 + Ninja 构建过；Linux / macOS 未验证。
  - **包体积 57 MB**：FFmpeg 的传递闭包占绝大部分（101 个 DLL）；要小包得关掉
    视频支持重编，而不是删 DLL。
  - **许可证口径**：闭包里的 GPL 组件（x264 / x265 等）不适用本仓库的 MIT，
    对外发布前需确认源码提供方式。
  - 中键只记状态、不派发；右键不产生 onPointerDrag；触摸只认第一根手指。
  - 长按阈值 0.5s / slop 8 设计像素是通用值，真机手感未调。
  - 单行输入框：多行、撤销 / 重做、Tab 焦点遍历、IME 候选窗定位未做。
  - 两种 svg 的边界不同：按钮的 AppearanceType::Svg 只认单图形（生成期转形状）；
    整张设计稿用 Image 的 type:"svg"（运行期按目标像素光栅化）。
  - SVG 里的 text / use / <image> / clipPath / mask / filter 不渲染，只打一条 WARN；
    导出时请把文字转曲、use 展开。整张稿也**不做元素级拆解**。
  - 没有 portal：子的 z 盖不过父级的兄弟，要压就抬容器自己。
  - **拖拽的边界（1.4，任务书 §4 明确不做）**：列表边缘**不会自动滚动**；
    不支持跨窗口 / 跨进程拖拽；不支持多选批量拖；没有排序 / 落位动画；
    payload 生命周期归调用方（库不解引用、不释放）。
  - **拖拽源没有"我被拖了"的逐控件查询**：要判就用
    `scene->GetDragSourceNode() == this`（一份真相，不在控件里存第二份）。
  - **幽灵的外观不可配**：配色 / 圆角 / 字号是库里的常量（`GhostLook`），
    `ghostText` 只换文案。要别的样子得改库或自己画一层。
  - **拖拽只跟主键**：右键不起拖，也不影响正在拖的那一场。
  - 运行期换肤只覆盖颜色（按钮三态 / 面板两态 / 标签文字色）；字号 token 是编译期的。
  - 背景板底图只做 cover（stretch / tile / 九宫格没做），且**不进主题表**——
    切主题换底图要改配置。
  - 透明窗口只在部分后端成立（D3D11 实测可用；D3D12 / Vulkan 多数不行）。
  - **抗锯齿（羽化）带仍按设计像素**（`kFeatherPixels = 1.0f`）：R≠1 时边缘那圈会失真。
    它与素材分辨率**无关**，按设备像素改造推迟到 1.x.x。
  - **比例锁没有**：`SDL_WINDOW_RESIZABLE` 恒开且未调 `SDL_SetWindowAspectRatio`，
    用户自由拖拽时 letterbox 留白必然出现——这是"UI 永不变形"的代价。
  - **素材偏小只在 DEBUG 构建里提示**：发布包没有任何日志。
  - **采样模式是进程级的**：像素素材与高清图平滑缩放同一进程只能二选一；
    且 software 后端的几何批不认采样模式（`SDL_RenderGeometry` 恒最近邻）。
  - **图集描述不能热更**：结构（帧矩形）进 exe，只有图片字节在 assets/ 里。
  - **嵌套两层滚动容器只有外层生效**：`FindSubtreeWheelOwner` 给的是"最近的声明者"，
    要内层优先得按指针路径逐层仲裁。一层是对的。
  - **文字纹理预算的瞬时上界是"预算 + 本帧新增"**：淘汰只发生在帧首，本帧刚烘出来的
    纹理不能丢（丢了当场缺字）；字形图集不参与淘汰。
  - **场地层没有可视示例**：库侧能用，但 `examples/` 里没有用它的场景——投影好不好看、
    斜得对不对，本版只有数字与像素采样背书，没有人眼确认过。
  - **场地是场景的固定槽位**：一个场景最多一个，而且必须**直接挂在场景下**（它提交
    绝对设计坐标，祖先带平移 / 缩放会整块错位——那里直接拒绝并 WARN 一次）。
  - **场地没有"实体"**：`InkingFieldObject` 是 POD，实体 / 系统链 / 黑板都在业务侧
    （派生用首成员 `base`，`SetObjects` 的模板重载自动传跨距）。
  - **格子模式下 `followPerspective` / `SetSkyColor` 不生效**：正俯视没有"远处变小"，
    地平线在屏幕外 ⇒ 没有天空区域。设了不报错，见 §7 `field_follow_perspective_inert`。
  - **`depth` 不参与视觉**：只用于占位（影子 / 选中框 / 吸附）；贴地且要遮挡的东西
    （草、石头、树根）必须当物体，不能当瓦片——地形面永远在物体面之下。

重新打包（维护者，三条命令）
  1. cmake --build build-release -j        ← 先构建。**不构建就打包会被第 3 步拦下**
  2. 改本文件（tools/BUILD.txt 是**手写母本**，脚本只拷贝、不会生成）：
     版本行 / 构建日期 / 产物哈希 / 本版内容 / 验证记录
  3. bash tools/package.sh                 ← 产出 dist/inking-<版本>[-<阶段>]-win64/
                                             + .zip + .SHA256SUMS.txt

  第 3 步开头有两道**护栏**：`include/inking.h`（版本号的唯一真相）比
  `build-release/bin/libinking.dll` 新时**直接失败**，并提示先重建；缺
  `inking_demo_selftest.exe` 也失败。理由：版本号与二进制原本互不比对，忘了重建
  会静默打出"标着新版本、装着旧代码"的包（文件名、BUILD.txt、校验和全都自洽，
  只有代码是旧的）。它抓不住"改了代码但忘了 bump 版本号"——那属于版本纪律。
