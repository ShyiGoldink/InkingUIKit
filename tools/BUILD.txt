本轮（2026-10-18）改了什么
  1. **局部层级（A8b）**：`zIndex` 从"全场景一条"改成"**兄弟之间**"——树序绘制 +
     兄弟内 z。父容器永远先于自己的子孙画，于是"面板 z=20、里面的标签 z=1"不再被
     底色盖掉（那是一条**不报错**的静默失效）。仍是严格全序，绘制 / 命中 / 子树仲裁 /
     动静合并共用同一个比较器。
  2. **截图**：`InkingWindow::RequestCapture(path)` / `Capture(path)` / `HasPendingCapture()`；
     `.png` 走 `SDL_SavePNG`（SDL ≥ 3.4），其它走 `SDL_SaveBMP`，**不新增 SDL3_image 依赖**。
     另有环境变量 `INK_CAPTURE=<路径>`：启动后第一帧零代码落一张图。
  3. **运行期主题（只做颜色）**：`theme/InkingTheme.h`。生成期仍按**烘焙主题**把 `$token`
     烘成字面量（= 默认色），同时把 token 名留在组件数据里；运行期 `SetActiveTheme("light")`
     一句话换肤。**字号 token 与 stroke / shadow / image / canvas / scroll 的颜色仍是编译期的。**
  4. **标签 `height` 写 `0`** 不再被判"必须大于 0"（与省略等价，产物里都不出现那一行）。

怎么用
  README.md 的「用预编译包（不编译源码）」一节给了两条路线**可直接复制**的
  CMakeLists.txt / CMakePresets.json / main.cpp。要点：

  1. 前提：MSYS2 UCRT64 的 cmake / ninja / gcc / sdl3 四件 / ffmpeg。
     **不能用 MSVC 链接本包**（MinGW 的 .dll.a 与 MSVC 的 .lib 互不兼容）。
  2. `find_package(inking CONFIG REQUIRED)` 之后会导出：
       inking::inking        库目标（传播 include / SDL3 / FFmpeg / 编译宏）
       INKING_SDK_DIR        SDK 根
       INKING_INKGEN         bin/inkgen.exe
       INKING_CXXCSS_DIR     examples/CXXCSS（配置样例）
       INKING_INKGEN_CMAKE   生成模块（include 它才有 ink_add_generated）
  3. 运行期：libinking.dll 用 POST_BUILD 自动拷到 exe 旁；SDL3 / FFmpeg 的 DLL
     需要 PATH 里有 C:\msys64\ucrt64\bin。找不到时**静默退出**（0xC0000135）。
  4. 音频必须显式 `AudioInit()`：窗口层只负责每帧 AudioTick 与关窗时 AudioShutdown。
  5. 排错先截图：设 `INK_CAPTURE=<路径>` 跑一次，比加日志快。跑自检会在 exe 旁留一个
     `Log.html`（日志），它不属于包内容。

已知限制（详见 README.md「已知限制」）
  - 只在 Windows + MSYS2 UCRT64 + Ninja 构建过；Linux / macOS 未验证。
  - 单行输入框：多行、撤销 / 重做、Tab 焦点遍历、IME 候选窗定位未做。
  - AppearanceType::Svg 没有画法（配置能写，运行期静默退回纯色 color）。
  - **没有 portal**：层级虽然是局部的（树序 + 兄弟内 z），但子节点的 z 盖不过**父级的
    兄弟**。要压住同一容器之外的内容，抬**容器自己**（`Select` 的 `expandedZIndex` 就这么用）。
  - **运行期换肤只覆盖颜色，且只覆盖三处**：按钮三态、面板两态、标签文字色。
  - **字号 token 是编译期的**：改字号要重新生成（那是几何：重排 + 重烘命中表 + 字图集）。
  - 包内不含 SDL3 / FFmpeg 的 DLL（运行期依赖，由使用方提供）。
