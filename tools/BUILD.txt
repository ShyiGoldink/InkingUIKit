================================================================

版本号      0.8.5
版本阶段    release          ← 0.x 发布版：可用、可集成，但 1.0 前不承诺跨版本 ABI 兼容
构建日期    2026-10-30 21:00（GMT+8）

许可        MIT（本仓库代码，见包根 LICENSE；第三方见 licenses/）

!! 升级提示：0.7.1 → 0.8.5 有两处**行为**变化与三处**签名**变化
   行为（都是"以前静默，现在按文档说的做"）：
     1. **标签的 `height` 现在是文字上限**。`TextOverflow::Clip` 是默认值，
        但此前从没实现过——长文案会画出组件框（实测 300×40 的标签把 7 行全画出去）。
        现在装不下的行整行不画，`TextLayoutResult::truncated` 为 true。
        **要恢复旧行为**：把该标签的 `height` 设 0（不限高），不需要改库。
     2. **字形图集满了会发一条 WARN**（以前完全静默），并且不再每帧重烘一遍。
        现象上没有变化（文字仍然正常显示，只是走"整段一张纹理"那条路），
        只是日志里会多一条，且文字量极大时首帧耗时涨。
   签名（0.x 不承诺 ABI，但会让旧代码编译不过）：
     3. `detail::fillShapeTextured` 去掉 `bool hasAlpha`（0.6.2 起它已没人读）。
     4. `inking::HitsThumb` 去掉 `bool vertical`（`ScrollBarMetrics` 已含轴信息）。
     5. `detail::AudioLoadFromMemory` 去掉 `AudioLoadMode`（从内存加载只有一种模式）。
   新增能力（不改既有代码）：
     6. `detail::SetTextureBudget(bytes)` / `GetTextureBudget()` / `BeginTextFrame()`：
        文字纹理的字节预算与 LRU 淘汰。**默认 0 = 不淘汰**，不调与 0.7.1 逐字节相同。
     7. `GlyphAtlasStats::full`、`TextCacheStats::textureEvictions` 两个观测口。
   历史（从 0.5.0 之前升级才需要处理）：指针钩子签名变化
     旧  void onPointerPress(bool press) / void onPointerClick()
     新  void onPointerPress(PointerButton, bool) /
         void onPointerClick(PointerButton, float designX, float designY)
   完整迁移样板见 docs/zh/CHANGELOG.md 的「0.5.0 / 变更」第 1 条。

本版内容（0.8.5 = 任务书 `docs/zh/plans/2026-10-30-text-layer-caps.md` 的 5 个任务，
三个批次在同一次发版里交付）
  - **按框高裁行**（T-01）：`LayoutText` 在 `maxLines` 之后按"累计行高 ≤
    `maxHeight − 上下 padding`"丢尾行并置 `truncated`；`InkingStaticLabel` 把
    `_height` 当 `maxHeight` 传进去（`MeasureLayout` 那条撑高的路传 0，否则
    "框多高"永远等于"一行高"）。**至少留一行**、**不缩字号**。
  - **图集满不再逐帧重烘**（T-02）：`TextLayer::glyphAtlasFull` 置起后整条逐字形
    路短路（改动前 19 次/帧、60 帧多烘 1140 次），只在 `ReleaseGlyphAtlas()` 复位。
  - **图集满发声**（T-03）：首次满一条 WARN（已用格数 / 上限 / 后果），
    `GlyphAtlasStats::full` 是可断言的观测口；静默失效清单第 13 条。
  - **纹理字节预算与 LRU 淘汰**（T-04）：`detail::SetTextureBudget(bytes)`，
    **默认 0 = 不淘汰**；`SceneLibrary::RenderScene` 每帧开头推帧号并按预算淘汰
    （丢之前先 `FlushGeometry()`，只丢本帧没用过的，字形图集不参与）。
  - **严格告警门**（T-05）：`ctest` 从 6 条变 7 条（`strict_warnings`）。同一批源
    （`src/` + `tools/inkgen/`）用 `-Wall -Wextra -Wshadow -Wcast-qual
    -Wuseless-cast -Werror -O0` 重编，有告警即红；目标 `EXCLUDE_FROM_ALL`，
    日常构建耗时不变。清掉 25 条真告警；`-Woverloaded-virtual`（`Activate` 被隐藏）
    显式 `-Wno-` 并注明原因。

怎么用
  1. 只想看效果：双击 bin/inking_demo.exe（ESC 退出，F11 全屏，右键有上下文事件）；
     或命令行跑 bin/inking_demo_selftest.exe，读末行"失败项：N"（退出码 = 失败项数，
     `ctest` 也是这么判的）。
     **不需要 MSYS2、不需要改 PATH**——DLL 就在 exe 旁边。
  2. 写自己的工程：见 README「用预编译包」两条路线；最快的是把
     examples/minimal/ 整份拷出去改：
       cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release \
             -DCMAKE_PREFIX_PATH="<本包根>;C:/msys64/ucrt64"
       cmake --build build
     把 <本包>/bin/*.dll 拷到 exe 旁（minimal 的 CMakeLists 已自动做）。
  3. 前提：编译需要 MSYS2 UCRT64 的 cmake / ninja / gcc / sdl3 四件 / ffmpeg。
     **不能用 MSVC 链接本包**（MinGW 的 .dll.a 与 MSVC 的 .lib 不兼容）。
  4. 升级旧代码先看本文件顶部的「升级提示」与 CHANGELOG：0.5.0 的指针钩子签名是
     **破坏性**的；0.7.1 → 0.8.5 有三处签名与两处行为变化（标签按框高裁行、
     图集满会发 WARN）。
  5. 排错先截图：设 `INK_CAPTURE=<路径>` 跑一次，比加日志快。
  6. 跑自检会在 exe 旁生成 LOG/ 目录（日志），不属于包内容，可删。

已知限制（详见 README「已知限制」）
  - 只在 Windows + MSYS2 UCRT64 + Ninja 构建过；Linux / macOS 未验证。
  - 中键只记状态、不派发；右键不产生 onPointerDrag；触摸只认第一根手指。
  - 长按阈值 0.5s / slop 8 设计像素是通用值，真机手感未调。
  - 单行输入框：多行、撤销 / 重做、Tab 焦点遍历、IME 候选窗定位未做。
  - 两种 svg 的边界不同：按钮的 AppearanceType::Svg 只认单图形（生成期转形状）；
    整张设计稿用 Image 的 type:"svg"（运行期按目标像素光栅化）。
  - SVG 里的 text / use / <image> / clipPath / mask / filter 不渲染，只打一条 WARN；
    导出时请把文字转曲、use 展开。整张稿也**不做元素级拆解**。
  - 没有 portal：子的 z 盖不过父级的兄弟，要压就抬容器自己。
  - 运行期换肤只覆盖颜色（按钮三态 / 面板两态 / 标签文字色）；字号 token 是编译期的。
  - 透明窗口只在部分后端成立（D3D11 实测可用；D3D12 / Vulkan 多数不行）。
  - **抗锯齿（羽化）带仍按设计像素**（`kFeatherPixels = 1.0f`）：R≠1 时边缘那圈会失真。
    它与素材分辨率**无关**，按设备像素改造推迟到 1.x.x。
  - **素材偏小只在 DEBUG 构建里提示**：发布包没有任何日志。
  - **采样模式是进程级的**：像素素材与高清图平滑缩放同一进程只能二选一；
    且 software 后端的几何批不认采样模式（`SDL_RenderGeometry` 恒最近邻）。
  - **图集描述不能热更**：结构（帧矩形）进 exe，只有图片字节在 assets/ 里。
  - **帧表不支持帧内偏移**（`spriteSourceSize`）：帧被裁过四周透明边时会抖，不做。
  - **文字纹理预算的瞬时上界是"预算 + 本帧新增"**：淘汰只发生在帧首，本帧刚烘出来的
    纹理不能丢（丢了当场缺字）；字形图集不参与淘汰，预算比图集（≈4 MB）还小时
    会**放弃淘汰**（否则每帧清空重烘，比不设预算更糟）。
  - ~~视频解码这条路是空的~~（**0.9.0 T-01 已解决**，本条保留的是 0.8.5 的状态）：
    `src/video` 的 FFmpeg 分支（`#if defined(INK_HAS_FFMPEG)`）**那时没有任何
    CMake 文件定义过**，所以 `InkingStaticVideo` 编进去的一直是"没有画面 → 退回
    兜底色"那条实现——能编、能链、功能是空的（与 0.6.x 的 `INK_HAS_SDL3_MIXER`
    漏定义同型）。0.9.0 起 `CMakeLists.txt` 探测到 FFmpeg 就定义该宏并私有链接；
    配套素材 `examples/demo/assets/probe.mp4`（320×240 / 30fps / 1 秒，
    由 `ffmpeg -f lavfi -i testsrc=size=320x240:rate=30 -t 1` 生成）与自检
    `video_decode_probe` 一起落地：断言"解出帧数 > 0、画面 320×240、丢帧 0、
    画面内部不止一种颜色（且看不到兜底色）"。

重新打包（维护者，三条命令）
  1. cmake --build build-release -j        ← 先构建。**不构建就打包会被第 3 步拦下**
  2. 改本文件（tools/BUILD.txt 是**手写母本**，脚本只拷贝、不会生成）：
     版本行 / 构建日期 / 产物哈希 / 本版内容 / 验证记录
  3. bash tools/package.sh                 ← 产出 dist/inking-<版本>-win64/ + .zip + SHA256SUMS

  第 3 步开头有一道**一致性护栏**：`include/inking.h`（版本号的唯一真相）比
  `build-release/bin/libinking.dll` 新时**直接失败**，并提示先重建；缺
  `inking_demo_selftest.exe` 也失败。理由：版本号与二进制原本互不比对，忘了重建
  会静默打出"标着新版本、装着旧代码"的包（文件名、BUILD.txt、校验和全都自洽，
  只有代码是旧的）。它抓不住"改了代码但忘了 bump 版本号"——那属于版本纪律。
