## 1. 阅读顺序

新接手或新开一轮，按这个顺序读，**不要从 `src/` 里随便挑一个 `.cpp` 开始**：

| # | 文件 | 读它是为了 |
| --- | --- | --- |
| 1 | `docs/zh/API.md` | 五分钟上手 + 文档地图 + 头文件索引（查符号先看这里） |
| 2 | `docs/zh/SKILL.md` | 编码与解耦规范（分层、类写法、命名、并发、提交前自检） |
| 3 | `docs/zh/InputDesign.md` | 命中 / 标脏 / 输入的设计约定（**最容易误解的一层**） |
| 4 | `include/anchor/InkingAnchor.h` | 定位层：锚点、偏移、尺寸、仿射（**它不认识"树"**） |
| 5 | `include/widget/InkingWidget.h` | 核心：树、标脏、命中、布局、输入派发 |
| 6 | `include/detail/InkingGeometry.h` | 跨层几何工具（裁剪链、子树包络） |

③ `anchor/` 不认识"树"，树语义的父指针是 `InkingWidget::GetParent()` 对**同一条指针**的
`static_cast`（一份存储、两个视图）。

## 2. 构建、运行、自检

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
cd build && PATH=.:$PATH ./bin/inking_demo_selftest.exe     # 读 stdout 末行"失败项：N"
```

- 产物是**动态库** `libinking.dll` + `libinking.dll.a`；导出走 `WINDOWS_EXPORT_ALL_SYMBOLS`
  （`.def`），**不**逐类标 `dllexport`——漏标不报编译错，只在链接 / 运行期暴露。
- **`INK_ISLOG` / `INK_ISDEBUG` 必须给**，否则日志与断言整段消失。
- 跑示例 / 自检要 `PATH=build:$PATH`（DLL 在 `build/`）。
- **`inking_demo_selftest` 退出会挂**（已知缺口，见根 `README.md`）：读 stdout 末行，
  **别信退出码**。
- 沙箱里 `SDL_IOFromFile` 可能对所有路径都失败 ⇒ 字体打不开、文字无法真栅格化。
  自检支持 `INK_TEST_FONT` 指定可读字体；"没字体"不等于"代码有缺陷"。

## 3. 头文件与类写法（10 条）

**第 1 条** 公开头**只放声明**，实现进 `.cpp`；只有一行的方法可以留在头里。
公开面的判断标准是**"调用者需不需要完整类型"**：需要就 include，只需要指针 / 引用就
前向声明。代价是有些方法必须搬到 `.cpp`（前向声明不能调方法）。

**第 2 条** **公开头不拖 SDL 进来。**

- 只前向声明：`struct SDL_Renderer;`、`union SDL_Event;`（**连 `union` 关键字都不能省**）；
- **SDL 类型的声明必须写在 `namespace inking` 之外**——写在里面会声明出一个
  `inking::SDL_Renderer`，与全局 `::SDL_Renderer` 不同，于是 SDL 调用"参数类型不匹配"；
- 同理，**可选依赖不许变成硬依赖**：`SDL_image` / `SDL_ttf` / `SDL_mixer` / FFmpeg
  用编译开关（`INK_HAS_SDL3_TTF` 等）隔离，"没装这个库就整包编译不过"是不可接受的。

**第 3 条** **写法上的三条硬约束。**

- **标脏的归属**：写入口 `[final]` **负责标脏**（在写入口内部统一完成）；钩子 `on*`
  **不负责标脏**，也不拦截写入口。
- **命名**：类 `PascalCase`、方法 `camelCase`、成员 `_camelCase`、常量 `kPascalCase`。
  **不用 `m_` 前缀**。
- **渲染只提交三角化，禁止 CPU 逐像素光栅化。** `InkingDraw` 那一层做的是"把形状变成
  顶点 + 三角化后交给 `SDL_RenderGeometry`"，不是自己逐像素写颜色。逐像素光栅化在本项目
  是明令禁止的：它把每一笔的开销从"一次 GPU 提交"变成"W×H 次循环"，而且缩放后必然糊。
  两条脏也分开记：**命中脏**（几何 / 可见性 / 层级 / 父子）与**重绘脏**
  （颜色 / 文字 / 变换），详见 §5。

**第 4 条** `#include` 用**尖括号**、路径**从 `include/` 根起算**（`<widget/InkingWidget.h>`）。
多写一段（`<include/widget/...>`）就找不到。

**第 5 条** 新文件统一 `#pragma once`，不再新增 `#ifndef` 宏 guard；改旧文件时顺手统一。

**第 6 条** **产物只落 `build/` 目录，源码树保持干净。** 生成物（`inkgen` 的输出、
`.def`、`compile_commands.json`）、编译中间件、可执行文件一律不出现在 `include/` 与 `src/`。
好处不只是整洁：源码树干净才敢用通配符扫描（本仓库的自检脚本大量这么做）。

**第 7 条** **契约头一律"声明即定义"**（头内 inline 空实现）。只声明的话，任何派生类都在
**链接期**炸 `undefined reference`——而且是"谁派生谁炸"，看不出是契约的错。

**第 8 条** 单例 / 注册表**必须**用**函数内静态量**，不用类的静态数据成员
（静态初始化 / 析构顺序问题，见 §6 第 12 条）。拷贝 / 移动四个全禁。

**第 9 条** **产物目录约定**：`libinking.dll` 与 exe **同目录**（`build/bin`）——
Windows 下 exe 按"自身所在目录 → PATH"找 DLL，分开放会变成"程序静默退出、无输出、
读不到退出码"，看着像根本没跑；导入库 `libinking.dll.a` 落 `build/lib`；
`install` 只装"库 + 头"（`bin` / `lib` / `include` 三处），不装示例与 `CXXCSS`。

**第 10 条** **文件夹与命名**：每个组件占**单一文件夹**（`include/<组件>/` + `src/<组件>/`
一一对称），只放自己的逻辑；静态组件以 `InkingStatic` 开头、动态组件以 `InkingDynamic` 开头
（通常两样都要）；通用工具以**名词**结尾（`JsonTool`）。
**判据：按"归属哪个子系统"定，不按"含不含 SDL"定**（`InkingMesh` 刻意不碰 SDL；
`HitTable` 住在 `scene/`）。

## 4. 验证（提交前必须过的六条）

**第 1 条** 构建必须过（`cmake --build`，0 warning 为佳，**error 一律不算过**）。

**第 2 条** 自检必须过：`inking_demo_selftest` 的**失败项 0**（读 stdout 末行）。

**第 3 条** 文档与实现**同步**：改了公开面就改 `docs/zh/api/*.md` 与 `CHANGELOG.md`；
改了设计约定就改对应设计文档，**并把条号冲突一并处理**（见 §6 顶部）。

**第 4 条** **能变成数值判据的自己验。** 像素 / 坐标 / 数量 / 顺序 / 计数——渲染类走离屏
读回比对；"看起来对"不算证据。典型判据：`BatchStats` 的提交次数、`GetBuiltRowCount()`、
`GetRepaintingNodeCount()`、`UnknownNameCount()`、`GetDisplayTransformRejectedCount()`。

**第 5 条** 需要"看 / 摸"的（窗口行为、字体观感、视频同步）**停下来交给用户**，
不要自己宣布通过。

**第 6 条** 别提交 `build/`、别提交生成的中间产物；CRLF 扫一遍
（`tr -cd '\r' | wc -c`）。

## 5. 两种脏：一张表

| | **命中脏**（hit dirty） | **重绘脏**（repaint dirty） |
| --- | --- | --- |
| 谁触发 | 几何 / 可见性 / 层级 / 父子 | 颜色 / 文字 / 透明度 / 展示倍率 / 装饰动效 |
| 消费点 | **帧首**（重建绘制列表，随后重烘命中表） | **帧末**（记账 + 静默计时清零） |
| 安静帧数 | `kHitQuietFrames = 3` | `kRepaintQuietFrames = 5` |
| 症状（标错时） | 颜色动画每帧白重建一次绘制列表 | 动效的"停没停"外部观测不到 |
| 出口 | `MarkStructureChanged()` | `MarkRepaintDirty()` |

**指针移动**既不是命中脏也不是重绘脏，它是第三种：**指针脏**（帧末清，表不重烘）。
详见 `docs/zh/InputDesign.md` §5。

## 6. 经验条目（稳定编号 1–112）

> **编号规则**：`●` = 被注释引用、按引用处语义回填；`†` = 编号未被引用、按本仓库约定补入。
> 新增条目**只能追加在 112 之后**，永远不要插入或重排。

1. † 先量再改。没有读数之前不要说"这里性能有问题"，也不要先优化。
2. † 一次只改一个变量；修不掉的 bug 先写成能一键跑出来的探针。复现优先于推理。
3. ● **生成器只把常量烘成字面量，构造时不查任何表。** 还没做的是"按布局生成专用查找"
    与"专属命中结构"这类**特化**——现在的生成类是"数据 → 字面量 → 走通用组件"，
    没有为某个具体布局生成更快的查询路径。要特化先证明通用路径是瓶颈（第 40 条的计数）。
4. † 注释写"为什么"，不写"做了什么"。做了什么代码自己会说。
5. † 不猜 API：动手前先 `grep` 本仓库。照源仓库推断曾导致重复移植，**链接期才炸**。
6. † 编译期能抓的别留到运行期（`enum class`、`constexpr`、`[[nodiscard]]`、`final`）。
7. † 静态分析 / 编译警告当朋友：一条 `-Wunused` 背后常是真漏了一个分支。
8. ● **公开头不拖 SDL 进来。** `struct SDL_Renderer;` / `union SDL_Event;` 前向声明，
   声明放在 `namespace inking` **之外**；只有三个公开头真的 include 了 SDL
   （`InkingBatch.h` 要 `SDL_Vertex`、`InkingDraw.h`、`InkingText.h`），它们属"框架内部头"。
9. † 头文件依赖最小化：能前向声明就前向声明，能放 `.cpp` 就放 `.cpp`。
10. † 别在头里定义非 inline 函数（ODR 违例：能编过、链接期炸或随机选一份）。
11. † 模板与纯头值类型（`InkingEvent<…>` / `Task<T>` / `Affine` / `TransformSpec`）不进导出表。
12. ● **注册表 / 单例 / 全局槽位一律用函数内静态量**，不用类的静态数据成员。
    类的静态数据成员在 `main` 之前按翻译单元顺序初始化，而"生成器登记的代码由某个静态
    对象的构造触发"完全可能——那就是静态初始化 / 析构顺序问题。
    反面代价：**"进程唯一"的槽位必须落 `.cpp`**（头内 inline 函数的函数内静态量每 TU 一份，
    DLL 与 exe 各持一份会**静默**失效）。
13. † 全局状态的初始化不得依赖别的翻译单元的静态对象；要依赖就延迟到首次使用。
14. ● **`#include` 路径相对 `include/` 根、用尖括号。** 多写一段就找不到文件。
15. ● **注册令牌必须记住"我到底进没进库"**（`_active` 那一份 bool）。注册可能被驳回，
    驳回的令牌是空转的——**析构时绝不能去注销**，否则会把正主从库里摘掉。
16. † 令牌用 `std::optional` **延迟构造**，不要塞进初始化列表。
17. † 令牌的成员声明顺序要排在**被登记的信息之后**：析构时 key 才全程有效。
18. ● **可见性不能靠"藏起来"。** `SetVisible` 是骨架变化 ⇒ 命中表跟着重烘，
    所以"展开的那一列点得到、收起之后点不到"是白拿的。反过来：靠挪坐标 / 改 alpha 来
    "隐藏"，命中表不会跟着变，就会出现"看不见但点得到"。
19. ● **几何变了必须通知场景。** 绘制列表里存的是**绝对坐标快照**，几何变了不通知，
    它的**静态子孙会停在旧值**——症状是"父动了、子留在原地"。
20. † **非拥有**指针必须在命名与注释里标出来（`_parent` / `_scene` 都标了）。
    标了才知道该不该 delete、以及对象比协作者活得久时会不会成野指针。
21. † 拥有型子节点由父节点析构负责；子节点先销毁时自己摘链。
22. ● **注销必须幂等。** 与第 15 条同族：重复注销 / 误注销的后果是"把正主从库里摘掉"，
    而症状出现在很久之后的另一次查找上。
23. † 回调里不要假设容器还活着（尤其"点一下就关掉这个场景"这种写法）。
24. † 遍历容器时不要增删元素；要么先拷快照，要么每步比一次结构代次（第 103 条）。
25. ● **声音不该跟着帧率走。** 音频推进用**真实流逝时间**（`deltaSeconds`），
    不用帧计数——帧率一掉，音高 / 节奏就跟着变。
26. † 时间差用单调时钟算，别用系统墙上时间（会被校时 / 夏令时拉走）。
27. † 一切"每秒多少"的量都要乘 delta；凡是不乘 delta 的，都要能说出为什么。
28. † 不要把 delta 累积成"帧数"再乘以常数——两处近似会叠成可见的漂移。
29. ● **`enable_testing()` 必须写在任何 `add_subdirectory` 之前。** 它只对"调用之后
    处理到的目录"生效，晚一步就会让子目录里的 `add_test` **静默失效**：测试照样编出来、
    手动跑也过，就是 `ctest` 列表里看不见（示例里的集成自检曾一直不在列表里）。
    同类"注册得太晚就静默消失"的坑要当 bug 对待，因为没有任何报错。
30. ● **不做静默兜底。** 兜底要么**不兜**（让问题可见），要么兜了**记一条 WARN**
    （`OptionBar` 给"没声明布局"补竖向默认时会 WARN）。静默兜底是本项目最怕的一类：
    配置写漏了、画面看着还行，但每个组件都白拿了一层默认装饰。
31. † 默认值要选"不生效"，不要选"看起来合理"（第 112 条那个阴影坑就是这么来的）。
32. ● **混合模式要显式开。** 抗锯齿边缘那种 0→1 的 alpha 过渡，前提是
    `SDL_BLENDMODE_BLEND` 打开；窗口层开过一次（`InkingWindow::Show`），
    **离屏自检也要自己开**——不开的表现是"边缘变硬"，很容易被当成抗锯齿写错。
33. † 图形状态（裁剪、目标、混合、缩放）切换要成对保存 / 恢复；"改了不还原"会在
    很远的地方报应。
34. ● **同一套设计语言集中在一处。** 五套预制件的默认外观（底色 / 描边 / 主色 / 圆角）
    散在五个 `.cpp` 里各写一遍，迟早出现"菜单是圆的、列表是方的"——两边单独看都对。
35. † 常量集中到 `config/` 或 `PrefabTheme`，不要在各处复制字面量。
36. † 生成器"没配就不输出"，不要替用户写一个默认值（第 30 / 112 条同族）。
37. ● **静态档收不到每帧 `Tick`。** 需要每帧推进的东西（视频解码进度、文字滚动）
    只能挂在 `onRender` 上——它是唯一每帧都会来的钩子。要 `Tick` 就得选动态档。
38. ● **绘制与命中必须读同一个来源。** 两边各读各的字段，就是"画的是一个、点的是
    另一个"；两边单独看全对，合起来才错。观测口返回值而不是引用时尤其要统一。
39. ● **先结清"当场改值"的账，再做时长判断。** 没配过渡的状态切换会把 duration 记成 0，
    如果先 `if (duration <= 0) return;`，这笔账**永远报不出去**（画面停在旧色）。
40. ● **计数是一等公民。** "功能全对、只是白干活"只有计数抓得住：批次提交次数、
    纹理缓存命中、命中表条目数、绘制节点数、重建次数。凡是"能合并 / 能缓存"的地方，
    都要有可断言的计数观测口。
41. ● **观测口要不要推脏，必须写死一条。** 结论是**不推脏**：按当前宽度排一次并缓存，
    宽度没变就直接给上一次的结果。观测口有副作用的话，"看一眼"就会改变行为。
42. ● **命中包络要跟着变换动**，即使当前不参与命中。否则哪天它改成吃点击，
    表里登记的仍是老位置。
43. ● **"省略即继承"的规矩要显式。** 典型：`hoverInheritsNormal` 为真就拿 `normal`
    覆盖 `hover`——想给悬停 / 按下**不同**颜色，必须显式把它关掉，否则那两份白写。
    与第 30 条同族：默认行为必须明确、可预期、可观测。
44. † 一个字段只有一处真相；需要"两份视图"时用 `static_cast` 视图，不要复制存储。
45. ● **`SDL_RenderTextureRotated` 的 `center` 是相对 `dst` 的**，不是绝对坐标。
    正负号与旋转中心这一处已经错过一次：文字与图片共用同一段变换代码，改的时候一起改。
46. ● **先解绑再销毁。** 外部 PCM 流那类"底层要求 stream 有效到轨道不再需要它"的
    API，销毁顺序反了就是 use-after-free，而且**只在有音频在播时**崩。
47. ● **"文字不参与命中"是条"半对"的规矩。** 标签默认不吃点击，所以改文字**不标命中脏**；
    但它**要占位**（尺寸、布局、包络全对），所以"不参与命中"不等于"可以不管几何"。
48. † 一处规则如果只能"半对"，就把另一半写进注释，不要留给下一个人猜。
49. ● **绕开批次的直接绘制，必须先登记批次边界**（`detail::NoteImmediateDraw()`）。
    否则你这一笔会被后刷出去的几何批盖掉，症状是"画了但一会儿就没了"、
    还与叠放顺序有关。纹理绘制本身就是批次边界。
50. † 提交顺序唯一：先批（无纹理）→ 再纹理 → 再"立即绘制"，每处切档都要显式登记。
51. † 缓存失效要"精确"：能只丢字形图集就别连纹理表一起清（那里还有图片）。
52. ● **三态颜色"全透明"要兜底成不透明黑。** `Normalize()` 里那条兜底不是为了好看，
    是为了**让配置写漏看得见**：三态 alpha 全 0 的东西在画面上根本不存在，
    而 `Normalize()` 会把它兜成一块不透明黑，于是"弹簧 / 占位块变成黑板"一眼就发现。
    推论：需要"只占位不露面"的东西**不能写全透明**（alpha 给 2/255）。
53. ● **路径全程 `std::filesystem::path`（Windows 上就是宽字符）。**
    窄串构造 `path` 在**中文目录 / 中文用户名**下会抛异常；`getenv("USERPROFILE")`
    拿到的是 ANSI/GBK，也不行——要走 `getModuleFileNameW` 那条宽字符路。
54. ● **滚动只改绘制，不标命中脏。** 子孙不进命中表（A8a），命中是递归实时问的、
    用的又是"当前子树变换"——所以滚动没有表要重烘，也没有账要记。
55. ● **"按着键切走、抬起事件永远不来"是一类问题。** 键盘如此，指针也如此
    （指针出窗口 / 窗口失焦）。必须做状态收尾，不能指望"下一帧会纠正"。
56. † 状态机要有"无输入也能回到安全态"的路径（失焦 / 切场景 / 重载配置）。
57. ● **要键盘就必须声明**（`WantsKeyboardFocus()`）。不声明就拿不到焦点，
    症状是"输入框点得进去但一个字都打不出来"，且**不报错**。
58. † 焦点是场景级唯一归属，只由场景改；组件自己存一份 bool 就会两边不一致。
59. ● **`FINGER_CANCELED` 也算抬起。** 系统把触摸收走时不处理，指针会永远停在
    "按着"——之后所有悬停判断都错，直到下一次点击。
60. † 输入事件先归一化成内部状态，再派发；不要让每个组件各认一套 SDL 事件。
61. ● **切渲染目标必须原样恢复。** 贴字形图集时要把目标切到图集纹理，而裁剪矩形、
    原目标都是"切换前"的；切回来不恢复，表现是"某些组件被剪、某些没被剪，
    还和叠放顺序有关"。
62. ● **裁剪 / 命中同源，别抄第二遍。** 容器裁剪链与画布内容视口共用同一份几何工具；
    抄第二遍就会分家——"画被剪的位置"和"点被剪的位置"分家就是这么来的。
63. ● **回调里可能把对象析构掉。** 所以 `Emit` 用**快照派发**（名单在派发开始时就拷好），
    于是"点一下就关掉这个场景"是安全的。
64. † 回调注册者要保证自己不比被订阅者活得长；必要时在析构里注销。
65. † 事件只通知、不标脏；标脏始终是写入口的活。
66. † 不做隐式"全局刷新"接口；可见的重算入口优于看不见的自动行为。
67. ● **被拥有的节点只能走 `RemoveChild` + `AddChild` 重新排序**，
    不要直接改它的 z 去"插队"——拥有关系与叠放是两件事。
68. † 不要让子节点直接改父容器的布局状态；让父容器自己重排（第 86 条）。
69. † 嵌套容器要防重入：重排过程中再触发重排，要么排队、要么置位延后。
70. † 尺寸为零 / 负数的容器要能安全走过全流程（除零与空矩形是高频崩溃源）。
71. † 文本 / 数字的格式化不要放在渲染路径里（每帧格式化等于每帧分配）。
72. ● **缓存键要覆盖所有影响结果的字段。** 排版缓存的键必须包含字体、字号、
    最大宽度、语言、行距……漏一个就是"改了某项却不生效"，而且极难归因。
73. † 缓存值要与键的生命周期绑定；键失效时值必须一起失效。
74. † 不要用指针值当缓存键（地址会复用）。
75. † 日志里带上模块名与关键 id；不带 id 的日志在并发场景下等于没有。
76. † 日志不要出现在每帧路径上（除非有开关）。
77. † 库不往 stderr 打调试输出，也不弹窗；错误通过返回值 / 计数 / 日志开关暴露。
78. † 失败要能退回：宁可这一笔慢一点，也不能让内容消失（字形图集满了就退回整段渲染）。
79. † 失败路径也要能被断言：拒绝、跳过、降级都要有计数器。
80. † 断言用来说明"不可能发生"，不用来做参数校验；参数校验返回错误。
81. † `noexcept` 只标真不会抛的函数；在它里面抛就是 `std::terminate`。
82. ● **worker 只做"打开 + 解码"，交付必须在主线程。** 解码线程只把结果（PCM 块 /
    解码帧）交回主线程，由主线程推进状态与绘制；碰 UI 的东西一律不在 worker 里做。
    典型违反："在解码线程里直接改组件字段"——不出错只是运气。
83. ● **基类不存整份 `XxxData`，新增字段必须显式搬一次。**
    组件的构造会逐字段把 `XxxData` 拷进基类 / 自己；漏一处的症状是
    **"配置里写了、运行期没生效"，而且不报错**。加字段时同步的地方通常有：
    `Data` 结构体 → `Normalize()` → 生成器发射器 → 组件构造函数 → （必要时）`Paint` / `Look`。
84. † 数据字段的默认值要与"字段不存在"可区分：能用 `std::optional` 就别用魔法值。
85. † 结构体的 `Normalize()` 必须幂等（跑两次和跑一次结果一样）。
86. ● **重算要显式且幂等，框架不做隐式扫描。** "什么时候重算"必须看得见
    （`Relayout()` / `MeasureContent()` 这类显式入口）；否则嵌套容器容易重入，
    而且没法解释"为什么这一帧慢"。
87. † 布局解算写成纯函数（输入 → 输出），不要在里面改状态。
88. ● **进程级记账故意不析构**（堆对象、退出时不 delete）。别赌静态析构顺序：
    那次实测崩溃就是"对象在库已析构之后才注销"，而它只在自检退出路径上出现。
89. † 线程池 / 管家的静态量同样不析构；要收尾就用显式的 `Shutdown()`，不要放析构里。
90. † 加锁前先问"这份状态真的跨线程吗"；不是为了并发而并发。
91. † 有意不加锁的地方必须把前提写出来（"场景只在 UI 线程构造 / 析构"）。
    前提比锁本身更有价值——前提变了就该加锁。
92. † 读多写少用值拷贝 / 快照，别用锁把热路径串起来。
93. † 原子量只保护单个变量的可见性，保护不了"两个字段要一起变"。
94. ● **同一件事写两遍就会分家。** 画布内容的位置换算与提交层搬顶点那一段必须同构：
    两份各写一遍就会出现"内容跟着容器转、裁剪框留在原地"。
95. ● **只有一份画法。** 列表行的选中态只是"把外观那一笔的显示色换成高亮色重画一遍"，
    形状 / 描边 / 阴影 / 文字全走与按钮相同的两个入口——不要为"看起来差不多"另写一份。
96. ● **缩放用"相对按下点的累计位移"，不要用本次事件的增量。** 增量每次都从
    按下那一刻的基准重算，除了第一帧以外全被算回原位——表现是"稍微拉开一点就弹回去、
    像在对抗缩放"。
97. † 拖拽类交互要定义"反悔"（Esc 还原 / 出界取消）；只做"提交"会让人不敢拖。
98. † 交互的可逆性优先于效率：能一步撤销的操作不要做成两步。
99. † 手感参数（阻尼、阈值、吸附距离）集中可调，不要散落成魔法数字。
100. † 一切"看起来像 bug"的现象，先问"是不是两处各写了一遍"（第 94 / 95 条同族）。
101. † 归因顺序：先看数据（计数 / 坐标），再看顺序（谁先谁后），最后才看算法。
102. † 修完 bug 留一条能复现的探针；没有探针的修复等于没修（第 3 条）。
103. ● **回调里可能把"后面某个"节点析构掉。** 只拷一份名单挡得住容器本身失效，
    挡不住野指针——所以每一步再比一次**结构代次**，变过就停掉本轮
    （剩下的节点下一帧照常收 Tick）。代价是一次整数比较。
104. ● **容器与它运行期重建的子项要绑成一层 z。** 只给容器一个高 z、项还是默认 0，
    就会出现"展开的那块背景被别人盖住、选项却浮在最上面"。容器在命中表里只有一条，
    表里排序看的就是它——所以 z 必须从容器本身开始整体提升。
105. ● **层次靠 1px 描边站住。** 亮色主题下相邻面的明度差很小，纯色块之间会糊在一起；
    一圈极细描边是最便宜、也最稳的分层手段（暗色主题则靠明度差就够）。
106. † 颜色一律 `0xAARRGGBB`；不要用"像素格式相关"的写法。
107. † 主题色用语义名（`$panelSurface` / `$title`），不要在各组件里写字面色值。
108. † 对比度是可用性问题，不是审美问题：正文与底色至少要保持可读的差值。
109. † 圆角 / 描边 / 阴影三件套统一由一处解算，不要各组件自己圆角。
110. † 动效要有"关掉"的路径（无障碍与低端机）；关掉后布局不能变。
111. † 一切时长、间距、圆角都从同一套刻度里取，避免"每个组件差 1px"的观感。
112. ● **默认装饰不能无条件生效。** 曾经给阴影一个"偏移为 0 的默认值"，结果**每个按钮
    都白拿一层阴影盖在自己身上**：整幅画面被压暗一层（纯白 `255,255,255` 读回来是
    `150,150,150`），而所有形状 / 颜色 / 混合都是对的——看起来就像"全局蒙了一层暗色
    遮罩"（2026-10-08 实测）。推论：装饰的默认状态必须是**不输出**，
    而不是"输出一个零值"（第 30 / 36 条同族）。
