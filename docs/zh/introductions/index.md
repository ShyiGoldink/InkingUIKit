# 介绍文档

这一层回答"**为什么这样设计**"：给每个主题一段通俗的说明，建立心智模型，不列 API 签名、不贴完整代码。

要查某个类有哪些字段和函数，看 [API 目录](../API.md)；要追某个决定的来龙去脉，看 [设计方案](../plans/)。

## 目录

- **[InkingAnchor：锚点定位](InkingAnchor.md)**
  项目里每个内容的定位都建立在两个百分比上。这篇说清 `InkingAnchorPoint` 的语义、为什么用百分比而不是手算像素，以及为什么锚点在 LetterBox 体系下尤其可靠。

- **[InkingShapeSpec：形状](InkingShapeSpec.md)**
  一个组件的轮廓只有一份定义，却要同时喂给渲染、命中、包围盒。这篇说清为什么用"假反射"结构体 + SDF、为什么三个派生量必须同源、以及"夹取还是断言"这两类校验的分界在哪。

- **[InkingTransform：变换](InkingTransform.md)**
  变换是通道，不是布局。这篇说清为什么"看起来在哪"和"实际占多大地方"要分成两条路、为什么原点取组件中心、以及正反两个方向为什么必须挨着写。

- **[InkingWidget：组件](InkingWidget.md)**
  组件是能进渲染树的最小单位，它的输入能力挂在接口上而不是另立节点类型。这篇说清"钩子即能力发现"、为什么按钮分语义位而不分设备位、以及 click 带坐标而 press 不带的原因。
