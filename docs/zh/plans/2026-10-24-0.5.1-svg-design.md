## 0. 结论（TL;DR）

本文的「原本的 svg 设计」= 设计工具（Figma / Illustrator / Affinity 一类）导出的**整张页面稿**：
一份文件里几十个 `path` / `rect` / `circle`、若干 `g` 与 `transform`、渐变与描边，尺寸等于设计画布
（如 1600×900）。用户裁定 0.5.1 只覆盖这个形态（元素级拆解不做，见 §7）。

核实后，缺口不是"SVG 没有画法"（那句文档已过期），而是**没有一条"整张 SVG → 运行期高清纹理"
的通路**：现有 `type:"svg"` 只接受**一个图形元素**、只用于按钮外观，`CXXCSS/Image` 明确拒收
svg（`Cxxcss.cpp:3517-3521`）。

本版拆 **8 个任务 / 3 批**，落地顺序：先让"一份 SVG 字节 → 一张按设备像素光栅化的纹理"
跑通（a），再接配置、补元素护栏与命中穿透（b），最后示例与文档（c）。

| 编号 | 任务 | 批次 | 对应来源 | 落点 | 代价 |

两条设计取向（后续取舍按它们判）：

1. **SVG 是图片格式，不是新外观类型。** 整张稿走 `AppearanceType::Image` 的纹理路：几何仍由
   `ShapeSpec` 决定、绘制仍走 `detail::PaintImage`、命中仍走 `HitTestShape`。不新增第二条
   "形状真相"，不改 `AppearanceType` 枚举。按钮的 `type:"svg"`（生成期转形状）保持原样，
   两条路**同名不同义**，由文档写清。
2. **按输出像素光栅化，但有预算、有分档、有计数。** 与文字高清同源（`RendererDeviceRatio`），
   但一张 3200×1800 的 surface 是 23 MB，必须有像素上限与档位淘汰；"光栅化了几次 / 命中几次 /
   钳了几次"都要成为可断言的计数（`AGENTS.md` §6 第 40 条）。

## 2. 基线事实（核实结论）

探针源码在 `build/probe_svg.cpp`、`build/probe_svg2.cpp`、`build/probe_svg3.cpp`（构建目录，
不入库）；探针直接链接本机 `SDL3_image.dll`（3.4.6），输出数字抄在下面。实现时这些探针转成自检。

### 2.1 运行期能力（SDL3_image 3.4.6 / nanosvg）

| 条目 | 判定 | 证据 |
| - | - | - |
| 库里有 SVG 入口 | **成立** | `objdump -p SDL3_image.dll`：导出 `IMG_isSVG` / `IMG_LoadSVG_IO` / `IMG_LoadSizedSVG_IO`；头文件声明"since SDL_image 3.0.0" |
| 自动识别 SVG | **成立** | `IMG_isSVG(auto) = 1`；`IMG_Load_IO(svg)` 返回 100×100（按内在尺寸） |
| 整张多元素稿可一次光栅化 | **成立** | 含 `rect + circle + g@transform + linearGradient + stroke` 的 1600×900 SVG → `IMG_LoadSizedSVG_IO(1600,900)` 返回 1600×900；背景 `0xFF101018` 与原色一致 |
| 尺寸语义：保持比例，不拉伸 | **成立** | 100×100 的稿给目标 200×100 → 返回 **100×100**；给 `0×0` → 固有 100×100；只写 `viewBox` 不写 width/height → 按 viewBox 1600×900 |
| 渐变 | **成立** | linearGradient 采样 `0xFFF3000B`（红端）；radialGradient 中心 `0xFFFFFFFF`、角 `0xFF000000` |
| 组透明 / 嵌套 `<svg>` / `stroke` + `dasharray` / `fill-rule="evenodd"` | **成立** | `opacity="0.5"` 采样 `0x7F00FF00`；嵌套区域 `0xFF00FF00`；dash 采样 `0xFF00FF00`；evenodd 孔洞中心 `0x00000000` |
| `text` / `use` / `<image href>` | **不支持，且静默丢** | 采样均为 `0x00000000`，无错误、无日志（`text` 与 `use` 直接不画） |
| `clipPath` / `mask` / `filter` | **不支持，且静默忽略** | 带 clipPath 的整块矩形角落仍是 `0xFF00FF00`（没被裁）；mask 同；`feGaussianBlur` 的元素照画（中心仍纯绿），模糊与否未单独断言——按"忽略 filter"记录 |
| 坏 SVG 会报错 | **成立** | 截断的 `<path d="M 0 0 L` → surface 为空 + `"Couldn't parse SVG image"` |
| 性能基线 | **成立** | 1600×900：**14 ms**、surface 5.76 MB；3200×1800：**63 ms**、23 MB（本机，Release） |

### 2.2 现有代码路径（缺口定位）

| 条目 | 判定 | 证据 |
| - | - | - |
| 图片外观只认 color / img | **成立** | `tools/inkgen/Cxxcss.cpp:3451-3526`；`type:"svg"` 明确报错（`:3517-3521`） |
| 图片纹理按**原始尺寸**解码，缓存键不含尺寸 | **成立** | `src/render/InkingText.cpp:557-566`（`IMG_Load_IO`）、`:678-679`（键 = `img\|name\|size`）、`:1099-1140`（`PaintImage` 收 `width/height/mag` 却没用它们决定解码尺寸） |
| 文字高清已有"按输出比例烘"的现成机制 | **成立** | `RendererDeviceRatio`（`InkingText.cpp:133-157`，取 min、≥1）、`kMaxTextRasterRatio = 3.0`（`:130`）、`currentRasterRatio`（`:160-172`）——SVG 可直接复用，不必新造比例来源 |
| 按钮的 `type:"svg"` 子集"能画" | **部分成立** | 生成期把 svg 的 `fill` 写进 `appearance.color`（`Cxxcss.cpp:2572`）、几何转成 `shape`（`:2417-2485`）；运行期按纯色填形状（`src/button/ButtonPaint.cpp:114-119`）。**能画，但只支持单图形、填充色一种、几何必须等于组件框** |
| 文档"`AppearanceType::Svg` 没有画法、静默退回纯色" | **不成立（已过期）** | `include/button/ButtonData.h:51`、`README.md:453` 的表述与上面的代码路径不符；这是 T-08 要一并改的一处 |
| 现有按钮 svg 子集有真实配置/测试覆盖 | **不成立** | `build-release/bin/inkgen.exe --validate CXXCSS/Button/svgPath.example.json` 输出"以 .example.json 结尾，按约定不参与生成，已跳过"；`selftest.cpp` 里 `grep svg` 无命中 |
| 命中穿透已有公开 API | **成立** | `SetHitPassThrough` / `IsHitPassThrough`（`include/widget/InkingWidget.h:461-469`）；标签默认用（`InkingStaticLabel.h:27`）；图片**默认不穿透**（`InkingStaticImage.h:27-28`） |
| 图片组件可承载任意字节 | **成立** | `InkingStaticImage::SetImageBytes` / `LoadAsset`（`src/image/InkingStaticImage.cpp:161-188`）；`refreshRenderAppearance` 把类型硬编码成 `Image`（`:81-90`） |
| `ImageBytes` 只是字节视图，无格式标记 | **成立** | `include/render/InkingText.h:56-62` |
| 基线自检 | **成立** | 2026-10-24 跑 `build-release/bin/inking_demo_selftest.exe`：末行 `== 失败项：0 ==` |

### 2.3 结论：缺的是三条通道

1. **解码通道**：没有任何地方按"目标设备像素"解码 SVG（只有 `IMG_Load_IO` 的原始尺寸）。
2. **配置通道**：`CXXCSS/Image` 拒收 svg；按钮的 svg 只能是"单图形 + 形状"。
3. **护栏通道**：`text` / `use` / `clipPath` / `mask` / `filter` 会**静默消失**，当前无任何提示；
   而设计工具导出的稿里这些元素很常见——"文字没了但没人说"正是本项目最怕的一类失效
   （`AGENTS.md` §7）。

## 7. 明确不做（避免反复讨论）

| 不做的事 | 原因 |
| - | - |
| 把整张 SVG 拆成**元素级控件**（每个 path 一个可点组件） | 需要 SVG 元素树 + 坐标映射 + 与 `AnchorData` 的绑定，是 0.6 的架构活；0.5.1 只承诺"整张稿一张纹理 + 可穿透" |
| 渲染 `text` / `use` / `<image href>` / `clipPath` / `mask` / `filter` | 本机 nanosvg 实测不支持（§2.1）；换 resvg 会引入新依赖与许可问题。**导出时把文字转曲、展开 use** 是本版的应对，T-04 负责大声提示 |
| 扩展按钮 `type:"svg"` 子集（g / transform / viewBox / stroke / 多子路径） | 用户选的是"整张界面稿"；按钮子集改走形状层，是另一条线，另案排期 |
| 构建期把 SVG 预渲染成 PNG 再烘字节 | 放弃候选（§T-01 D）：放大糊、改稿要重跑外部工具 |
| API 专页（`docs/zh/api/InkingSvg.md` 之类）与 `API.md` 索引 | 用户裁定：**实现完成后再写**；本批只同步 `CHANGELOG` / `CXXCSS.md` / `README`。API 阶段顺带改 `docs/zh/api/InkingCxxcss.md:172` 那句"生成链仍在落地"（0.5.1 落地后它过期了） |
| SVG 动画（SMIL / CSS animation / `<animate>`） | nanosvg 只做静态快照；本版不引入时间轴驱动 |
