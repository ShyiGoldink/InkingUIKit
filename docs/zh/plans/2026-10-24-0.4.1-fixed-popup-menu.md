## 0. 结论（TL;DR）

用户提的 4 件事拆成 **10 个任务 / 3 批**。核实结论：

- **"吃掉"这一半已经成立**：动态 Block 与静态答案按 `IsAbove` 合并，探针 P3 实测通过（`QueryHit → popup, kind=Block`）。
- **"透传"这一半不成立，且本版不做**：探针 P4 显示动态 PassThrough 压住静态按钮时不会落层。**用户裁定：浮窗语义固定为吃掉，透传是扩展语义、允许跳过**，于是它从任务降级为 §7 的一条明确不做。
- **采样时机要改**：动态组件现在在 `onTick`（固定 50Hz 逻辑步）里自判，用户裁定改为**响应指针变化事件再拉**——"鼠标不动就不动"，允许一帧错位。这一条取代了原计划里的"动态自判时机"。
- **真缺口是输入归属的不对称**：静态容器会把答案深挖到子控件（靠场景推），动态容器不会（探针 P1），于是浮窗里的按钮"看得见、点不到"。

三条设计取向（后续所有取舍按它们判）：

1. **输入语义只有一条**：一个点上只有一个归属，它是 `QueryHit` 给出的那个 Block，而且它必须**接得住**这次输入。静态接住 ⇒ 场景推**结果**；动态接住 ⇒ 场景在**指针变化时**通知它，它自己拉**状态**。两档对同一份几何给出同一个答案，差异只在投递方式与时机。
2. **场景层只改两处**：命中答案（深挖）与"指针变化"的通知时机。`DispatchPointer` 的捕获 / 悬停 / 拖动 / 滚轮 / 焦点五段逻辑一行不动——动它们的回归面远大于收益。
3. **先统一语义再加能力**。第一批把"谁接住、什么时候接"钉死，第二三批的浮窗直接继承结论，不自己造一套"我判断点在不在我身上"的旁路。

两个值得记下来的细节：

1. **`downEdge` 与 `pressed` 必须分开**。前者是"发生了按下"，后者是"按下算在我身上（捕获）"。任何"点外部就关"的组件要的是前者——拿自己的命中状态去过滤就退化成后者，菜单会永远关不掉。
2. **`OpenAt` 里 `Relayout()` 必须在 `applyPlacement()` 之前**。内容刚挂上去时尺寸还是旧值，落位会拿错尺寸算钳制（不报错，只是位置偏了）。这条写进了源码注释。

## 7. 明确不做（避免反复讨论）

| 不做的事 | 原因 |
| - | - |
| **跨静态 / 动态的点击透传** | 用户裁定为**扩展语义**、本版不排期。真要做要同时改 `QueryHit`（三态合并）与 `DispatchPointer`（它现在完全不看 `HitKind`），属于"改派发架构"那一档，得单独一批 + 最长观察期 |
| 浮窗提供穿透开关 | 浮窗语义固定为"吃掉"。继承来的 `SetHitPassThrough` 在文档里标注"不是给浮窗用的"；要穿透请直接用裸 `InkingDynamicWidget` |
| 动态组件在逻辑步里自判输入 | 已改为"指针变化时通知"（T-02/T-03）。`onTick` 仍保留，但它只管几何推进 / 计时，不再管输入 |
| 把边沿判定塞进 `InkingButtonLike` | 那个类是三态专用（有外观、有过渡）；浮窗 / 列表行不该被按上三态。分工：`PointerProbe` 产结论、`InkingButtonLike` 吃结论 |
| portal / 堆叠上下文 | 0.4.1 靠"给浮窗高 z"（默认 400）。父级的兄弟仍盖不住——那是 `InputDesign.md` §15 第 3 条，没变 |
| 浮窗每帧跟随鼠标 | 每次 `ChangeOffset` 都 `MarkStructureChanged` ⇒ 每帧重烘整张命中表。定点浮窗是"打开时定位一次"的语义 |
