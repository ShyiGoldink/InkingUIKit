# 设计记录：Vue 当前端口子，C++ 起本地服务（重构期的外部契约）

> 状态：**提案**（2026-11-22；待试点阶段 0 验证）
> 日期：2026-11-22
> 来源：讨论"Vue 搭界面 + C++ 做 core 是否可行"；结论是走**进程外本地服务**这条路
> 目标版本：不随库版本发布（工具侧实验，不进口 `include/`）
> 涉及层：新增 `tools/bridge/`（不进库）；`docs/zh/plans/`；**不改** `src/` 与 `include/`

---

## 0. 结论（TL;DR）

可行。但它的成立条件不是"少写 C++ UI"，而是**重构期需要一个外部契约压住内部乱动**：

1. 协议在进程外 → core 内部怎么重构都不动 Vue，这是唯一一条"重构可以乱、契约不变"的路。
2. 定位是**口子/内测形态**，不是最终交付形态。写清楚这一点，这条路就不产生架构债。
3. 三条硬底线（破任何一条即停）：只 `bind 127.0.0.1` + 一次性 token；**先协议后界面**；不暴露控件树。

明确放弃的三个候选（理由见 §2）：

| 放弃的候选 | 为什么不做 |
| - | - |
| 进程内 FFI（node addon / cxx） | 库是 MinGW ABI（README 已写"MVSC 不能链"），addon 会把工具链和 Node ABI 双锁死 |
| 内嵌 WebView2 / CEF（方案 A） | 现在做等于在重构期把"窗口-合成-输入"三条线一起改，风险叠加；留作 §7 之后 |
| `--app` 模式找 Chrome/Edge 路径 | 找不到就退化到默认浏览器，体验断崖，且要维护三平台路径探测表；不值得 |

## 1. 范围

| 做 | 不做 |
| - | - |
| HTTP 发静态资源（Vue 的 `dist`） | REST + WebSocket 混用两套心智模型 |
| 一条 WebSocket 承载全部交互 | 把 C++ 类反射成命令（RPC 自动映射） |
| 手写命令表（枚举 + 分派） | WS 里传 base64 图片 / 二进制帧 |
| 握手交换能力集 | 多标签页并发写同一份状态 |
| 错误码用字符串枚举 | 版本不匹配还"尽量跑" |

两条贯穿的不变量：

1. **一条连接一个会话。** 第二个标签页连上来要么顶掉第一个（并明确提示），要么被拒；不允许两个会话同时下命令——否则"谁改了场景"无从回答。
2. **命令表是唯一真相。** 文档、mock、core 三份实现都从同一张表生成或对照；任何"临时加一条"都是下一次事故的种子。

---

## 2. 为什么是这条路（对"重构期"的适配度）

| 方案 | 重构期适配度 | 理由 |
| - | - | - |
| 内嵌 webview（方案 A） | 低 | core 在重构时它同时改窗口、合成、输入三条线，缺陷无法归因 |
| **本地服务 + 浏览器（本方案）** | **高** | 边界在进程外；core 崩了 Vue 只是断线，能分清是谁的问题 |
| 进程内 FFI | 低 | ABI 与工具链锁死，重构期最不能接受 |
| C++ 编 wasm 塞进 Vue | 中 | 零 IPC 很香，但 SDL3 + FFmpeg 的 wasm 化是另一个项目，重构期不叠加 |

一句话取舍：**重构期要的是"能分清楚是谁坏了"，不是"跑得最快"。** 进程隔离是唯一同时满足这两点的边界。

---

## 3. 进程与生命周期

| 项 | 决定 | 理由 |
| - | - | - |
| 端口 | `bind 127.0.0.1:0`，内核分配，读回实际端口拼进 URL | 固定端口会撞；写死端口的工具在第二台机器上翻车是常态 |
| 地址 | 只用 `127.0.0.1`，不用 `0.0.0.0`、也不首选用 `localhost` | `localhost` 可能解析到 `::1`，两边 bind 不一致就是"页面打不开" |
| 单实例 | 命名互斥体（Win）/ `flock`（Linux）；第二次启动直接退出，可选把 URL 交给已有实例 | 双击两次抢端口是第一天就会遇到的 bug |
| 退出 | 最后一个 WS 断开 + N 秒无重连 → 退出（`N` 可配，默认 5） | 否则关掉标签页留下一个孤儿进程 |
| 打开浏览器 | `ShellExecuteW` / `xdg-open`；**失败就打印 URL 后阻塞等待** | 静默失败会让用户以为程序没启动 |
| 静态资源 | 读 `dist` 目录，`index.html` 兜底（history 路由） | 不引入任何第三方 HTTP 库也够用 |

---

## 4. 安全底线（这四条不是洁癖）

一个监听本机端口、能读写文件的进程，是标准的本地提权面。

1. **Origin / Host 校验。** 只认 `http://127.0.0.1:<port>`，其他一律 403。防 DNS rebinding（攻击者页面用域名解析到 127.0.0.1 来打你的端口）。
2. **一次性 token。** 启动生成随机串，塞进 URL；WS 首帧校验，不匹配立刻 `close` 且不解释原因（解释等于给爆破者一个 oracle）。
3. **路径必须过"允许根"检查。** 所有带 id 的资源命令解析成绝对路径后，必须仍在允许根下（规范化后再比较前缀，不是字符串 `find`）。`/asset?id=..%2f..%2fetc%2fpasswd` 这类用例要进验收。
4. **静态资源带 CSP。** `default-src 'self'`，不放开 `unsafe-eval`；资源文件名带 hash，不做运行期拼路径（用户浏览器可能装了改写请求的扩展）。

## 5. 协议形态

骨架只四个字段，所有扩展都在 `payload` 里：

```
{ "v": 1, "id": "c-17", "type": "cmd.scene.list", "payload": { } }
```

| 约定 | 内容 |
| - | - |
| 方向前缀 | `cmd.*` 客户端→服务端；`evt.*` 服务端→客户端。看前缀就知道谁发起 |
| 握手 | 客户端 `hello {v, token, capabilities}` → 服务端 `welcome {capabilities, limits}` |
| 能力集 | 服务端声明支持的命令；不支持的命令**Vue 侧隐藏入口**，不是点了才报错 |
| 二进制 | 走独立 HTTP 端点 `GET /asset/<id>`，WS 里只传 id |
| 错误 | `{code, message, detail}`；`code` 用字符串枚举（`scene.not_found`），不用数字 |
| 版本 | 握手 `v` 不匹配直接拒绝，两侧版本号都打日志；不做兼容层 |
| 日志 | 每条命令一行：`id / type / ms / ok|code`。出问题能靠日志还原一次会话 |

**为什么不用 RPC 反射：** 反射出来的命令不可枚举 → 写不出文档、写不了 mock、做不了版本兼容，而且参数校验只能靠"运行时崩了才知道"。手写命令表 20 条也就 200 行。

## 6. 与 Inking 对接（重构期怎么切）

| 阶段 | 内容 | 出口条件 |
| - | - | - |
| **0** | 只写协议 + mock server（不碰 Inking 一行）。Vue 对着 mock 全速开发 | Vue 侧能跑通 20 条命令的假数据 |
| **1** | 接**一条**只读真实命令（如 `cmd.asset.list`），跑通链路，量 RTT | 本机 RTT p95 < 5ms |
| **2** | 逐个暴露"已重构完且稳定"的模块：asset → render 快照 → text layout | 每个模块附一条契约测试 |
| **3** | 判断点（见 §7）：Vue 能不能干掉 90% 的界面 | 能 → widget 层可议退役；不能 → 止损 |

**一条红线：永远不暴露 `InkingWidget` 控件树。** 一旦把控件树映射成 JSON 发给浏览器，等于用 JSON 重新实现一遍布局与命中——比现在慢、比现在脆，还把重构中的内部结构钉死在协议上。暴露的只能是**数据与结果**（场景快照、布局求解结果、纹理 id），不是**对象**。

---

## 7. 判断点：什么情况下这条路该停

| 触发条件 | 为什么这条路给不了 | 该换哪条 |
| - | - | - |
| 需要手写笔 / 笔迹实时上屏 | 浏览器合成 + 事件合并，16ms 内做不到 | 回 native |
| 需要窗口透明 / 无边框 / 置顶 / 点击穿透 | 浏览器窗口不归你管 | 回 native（`examples/pet` 那类） |
| 需要在 Vue 布局里塞 >60fps 的自绘画布 | 要么 canvas + wasm（另一个项目），要么 native 子窗口（方案 A） | 方案 A / wasm |
| 需要"看起来像原生应用"的交付形态 | 任务栏显示的是浏览器、Alt+Tab 是浏览器 | 方案 A |

**这四条都命中任意一条，就说明"口子"已经超出它的职责。** 在那之前它一直是划算的。

---

## 8. 验收（可断言）

1. 冷启动到首帧 < 1.5s（含 Vue 首屏渲染）。
2. WS 命令 RTT（本机 echo）p95 < 5ms。
3. 单实例：二次启动退出码 0，且不产生第二个监听端口。
4. 错误 token / 非法 Origin → 连接被拒，且日志有对应记录。
5. 路径穿越用例（`..%2f` 变体三种）全部返回 404，无文件内容泄漏。
6. 关掉最后一个标签页后 5~7s 内进程退出（`N=5` 配置下）。

## 9. 风险与回退

| 风险 | 表现 | 回退 |
| - | - | - |
| 变成"永久临时方案" | mock 层没人维护，协议与 core 渐渐不一致 | mock 由协议文件生成，与 core 共用同一张命令表；协议改动必须同时改三处，否则 CI 红 |
| 浏览器不可控 | 用户装了改请求的扩展、企业代理截走 127.0.0.1、老版本不支持某 API | 启动做能力探测（页面发 `hello`，超时即判不兼容），明确提示而不是白屏 |
| Vue 与 C++ 的 UI 同时生长 | 两套外观定义，改一处漏一处 | 定死"外观只在一处定义"；CXXCSS 若保留，只覆盖 native 侧核心组件，不做跨端对齐 |
| 端口被安全软件拦 | 首启弹防火墙提示，用户点拒绝 | bind 失败要有明确文案（"本机端口被占用/被拦截"），不吞错误 |

## 10. 待定（下次讨论）

- `N` 秒自动退出的默认值是否该反过来——core 常驻、浏览器只是视图？取决于有没有"后台任务"这类需求。
- 静态资源要不要支持热更新（Vite dev server 代理到 core），还是只服务 `dist`。
- 命令表放哪：`tools/bridge/protocol.json` 单一来源，还是 C++ 头文件 + 生成 TS 类型。倾向后者（TS 类型能直接约束 Vue 侧）。
