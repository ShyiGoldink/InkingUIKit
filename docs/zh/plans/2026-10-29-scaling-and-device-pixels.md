## 0. 结论（TL;DR）

讨论走完四轮后，结论有两条**取舍**性质的转变，必须先写在最前：

1. **接受"边缘略糊"，不在 0.7.x 修**——羽化带按设备像素改造（原 T-02）推迟到 `1.x.x`。理由是它与素材分辨率无关，代价却是改动顶点缓存键（有回归风险）；当前优先保功能面。
2. **不做运行期重采样、不做缓存表**——本库的取向是"内存换效率"（原像素常驻、素材预先出大），再叠一层按目标尺寸的缓存表会把内存推向失控。因此"任意尺寸不失真"这条**放弃**，清晰度改由**一条静态规则**保证：素材按目标屏幕像素出，纵深落在整数档。

据此拆成 **4 个任务、2 个批次**，全部是零运行期内存增量：

| T-01 | 验证栅格化发生在设备分辨率 | 0.7.0 | A1 | `examples/demo/selftest.cpp` | 低 |

设计取向三条：

1. **抗锯齿与视觉元素分开算**——描边宽度 / 圆角 / 字号是**视觉元素**，跟设计像素走是对的；抗锯齿带是**手段**，理论上该按设备像素恒定。这条判断保留，只是**执行推迟**。
2. **规则要做成可测的代码，不是散文**——所以 T-02 是一个纯函数（与 `ImageFitSpec` 同一形态），文档引用它，自检断言它。写在 README 里的公式没人验。
3. **不新增运行期内存**——T-03 只加一个数值与一条日志，T-04 只在 DEBUG 编译，T-01 只加自检。这是本版能收敛到 4 个任务的原因。

## 3. 缩放规则（对使用者与美术的约定）

这一节是 §T-02 的规格说明，也是文档要写的**对外承诺**。

### 3.1 四个量

```
R  = min(窗口物理宽 ÷ 设计宽, 窗口物理高 ÷ 设计高)    ← letterbox 倍率，库内算
S  = 组件设计尺寸 × 纵深 × R                           ← 它在屏幕上的物理像素
σ  = 素材像素 ÷ (组件设计尺寸 × 纵深 × R)              ← 采样比
R_max = min(最大目标屏宽 ÷ 设计宽, 最大目标屏高 ÷ 设计高)
```

### 3.2 规则一：素材按"屏幕像素"出，不按"设计像素的倍数"出

```
素材像素 = 组件设计尺寸 × 纵深 × R_max
```

关键推论：**素材的绝对像素只取决于"这个组件最大占多少屏幕"，与设计尺寸无关。**

| 设计尺寸 | 全屏 4K 的 R | 按"2×设计"出图 | σ | 按屏幕像素出图 | σ |
|---|---|---|---|---|---|
| 1920×1080 | 2 | 3840 宽 | 1.0 ✓ | 3840 | 1.0 ✓ |
| 1280×720 | 3 | 2560 宽 | 0.67（放大 1.5×，糊） | 3840 | 1.0 ✓ |
| 640×360 | 6 | 1280 宽 | 0.33（放大 3×，糊） | 3840 | 1.0 ✓ |

所以"设计尺寸小"本身不导致糊——糊的原因是素材按设计倍数出。设计尺寸只是坐标刻度。

### 3.3 规则二：纵深必须落在 `素材倍率 ÷ 整数` 上

不做 mip、不做重采样，就意味着**每个显示尺寸都必须靠"素材正好那么大"来保证 σ=1**。当纵深变化时，σ 会变，而**非整数 σ 会有纹素被完全跳过**（表现是细节在运动时游走/闪烁），比"缩得多"更难看。

干净档位 = `d = m / k`（m = 素材倍率，k = 正整数）：

| 素材倍率 m | 干净纵深档位 |
|---|---|
| 1× | 1.0 / 0.5 / 0.333 / 0.25 |
| 2× | 1.0 / 0.667 / 0.5 / 0.4 / 0.333 |
| 0.5× | 0.5 / 0.25 / 0.167 |

所以"选素材倍率"和"定纵深档位"是同一件事，必须一起定。

σ 判定：

| σ | 含义 | 观感 |
|---|---|---|
| = 1 | 1:1 | 最清 |
| 整数且 > 1 | 缩小，双线性≈k×k 盒式 | 干净（但信息只剩 1/k²） |
| 非整数 | 部分纹素被跳过 | 脏，运动时闪 |
| < 1 | 放大 | 软（linear）或块（nearest） |

### 3.4 规则三：边缘模糊有四个成因，本版只解一半

| 成因 | 何时出现 | 归属 | 本版 |
|---|---|---|---|
| 抗锯齿带按设计像素 | 永远；R≠1 即失真 | 库缺陷 | **推迟 `1.x.x`**（§7） |
| 素材不足（σ<1） | σ<1 | 使用者 | T-04 提示 |
| 非整数 σ 的采样不均 | 纵深非 `m/k` | 使用者 | T-02 规则 + 文档 |
| 非整数 R 的像素不均 | 仅 nearest | 选择 | 不适用（进程级 linear） |

注意第 1 项**独立于**其余三项：设计 640 + 4K 全屏时，把素材补到 3840 也救不了边缘，因为羽化在**顶点 alpha** 上，与采样无关。这解释了为什么"本版接受略糊"是一个可接受的取舍——它不影响素材分辨率的正确性。

## 7. 明确不做 / 推迟（避免反复讨论）

| 事项 | 结论 | 原因 |
| - | - | - |
| **羽化带按设备像素**（原 T-02） | **推迟 `1.x.x`** | 它与素材分辨率无关（羽化在顶点 alpha 上），而改造要动顶点缓存键、有回归风险。当前优先保功能面，接受"小设计尺寸 + 大屏"时边缘略糊。判断本身保留（§3.4 第 1 项），只是执行推迟 |
| **按目标尺寸重采样的缓存表 / GPU mip 链** | **不做** | 本库取向是"内存换效率"（原像素常驻、素材预先出大），再叠一层按尺寸的缓存表会把内存推向失控。技术可行（`SDL_SetRenderTarget` 就在），但收益抵不上内存 |
| **"任意尺寸不失真"** | **放弃** | 它是上一条的直接后果。清晰度改由**静态规则**保证：素材按屏幕像素出（§3.2）+ 纵深落在整数档（§3.3） |
| **逐图采样模式** | 延后 | 0.6.4 的进程级 `SetImageSampling` 已覆盖"整套素材都是像素风"的常见情况；逐图只在混用时才需要，且要多一张纹理（与内存取向相反）。等真有人要再做 |
| **换 SDL_GPU** | 不做（本版） | 它解决的是"没有着色器"（逐像素光照），不是缩放。等昼夜循环开工时单独评估——届时顺带能拿到原生 mip |
| **昼夜循环 / 光源合成** | 暂缓（大工程） | 技术路线已探明：`SDL_BLENDMODE_MUL`（`dstRGB = src*dst + dst*(1-srcA)`）精确对应"白=亮、灰/黑=暗、透明=不处理"，一个混合模式可覆盖**固定档**光照。注意 `MOD` 少一个 alpha 项，透明区会变黑。方向可调需要法线来源，而**单张灰度 + 已知光源方向推不出法线**（一个方程两个未知数），必须先定美术给高度图还是 N 档 |
| **九宫格 / tile** | 不做 | 与 `ImageFitSpec::DrawnRect`（整张等比缩放）语义正交，且当前无 HUD/边框用例。等真有需求时按"细分 quad + UV 策略族"一次做 |
| **离屏整数倍缩放** | 不做 | 只为像素风的"像素均一"服务。非整数 R 在 σ=1 的双线性下无害（§2.1 的 A6），而本库素材是绘画素材不是像素画 |
| **相机 / 相机倍率 / per-image 渲染倍率** | 不做 | 前者用户明确排除（2.5D 靠分层与纵深缩放）；后者的倍率由 §3.2 推导，不该逐图手配 |
| **`fillVertices` / 逐顶点色 / 可写像素表面** | 不做（本版） | 已被"光照走 MUL 混合"与"光照整体暂缓"同时取代。等昼夜循环真开工时重新评估 |
